# 《CodeDance: A Dynamic Tool-Integrated MLLM for Executable Visual Reasoning》中文精读翻译

## 论文信息

- **英文标题**：CodeDance: A Dynamic Tool-Integrated MLLM for Executable Visual Reasoning
- **中文标题**：CodeDance：面向可执行视觉推理的动态工具集成多模态大模型
- **作者**：Qi Song*、Honglin Li*、Yingchen Yu、Haoyi Zhou、Lin Yang、Song Bai、Qi She、Zilong Huang†、Yunqing Zhao†（* 同等贡献；† 通讯作者）
- **机构**：北京航空航天大学（Beihang University）、西湖大学（Westlake University）、字节跳动中国（ByteDance China）、字节跳动新加坡（ByteDance Singapore）
- **arXiv 链接**：https://arxiv.org/abs/2512.17312
- **提出的框架**：CodeDance——以可执行 Python 代码作为统一推理媒介的动态工具集成（Dynamic Tool-Integrated）多模态大语言模型（MLLM），通过"思考—执行—反馈"的多轮循环编排视觉-符号操作，并在强化学习阶段引入基于组级准确率（group-level accuracy）的难度自适应工具调用奖励 $R_{\text{BAT}}$，实现"难题多调工具、简单题少调工具"的平衡调用策略。

## 一句话核心总结

CodeDance 把"可执行代码"当作视觉推理的通用求解器：模型不再受限于"预测边界框坐标再裁剪"这类固定模式（schema）的单步流水线，而是自主定义、组合并执行 Python 代码来编排多种视觉工具、计算中间结果、渲染可检验的视觉证据（框、线、图等），从而实现透明、可自我校验的多轮推理；配合 34K 高质量冷启动轨迹数据（弱到强过滤 + 多轮原子监督）与"序列级组准确率自适应奖励 + 回合级执行惩罚"的两级奖励 $R_{\text{BAT}}$，7B 规模的 CodeDance 在计数、视觉搜索、图表问答与数学推理等 10 余个基准上超越 GPT-4o 与更大的开源模型（如 Qwen2.5-VL-32B），并在 RL 训练中自发涌现出跨任务工具迁移、新颖工具组合等未被显式监督的行为——一句话：用代码统一了"怎么用视觉工具"，用组级准确率把"何时用工具"变成了可优化的学习信号。

## 摘要（完整翻译）

近期发布的 o3 等系统展示了类人的"带着图像思考"（thinking with images）推理能力——将工具使用与逐步验证相结合；然而大多数开源方法仍然依赖纯文本思维链、僵硬的视觉模式（visual schema）或单步流水线，这限制了它们在复杂任务上的灵活性、可解释性与可迁移性。我们提出 CodeDance，探索将可执行代码作为视觉推理的通用求解器。与固定模式的调用方式（例如仅预测边界框坐标）不同，CodeDance 通过定义、组合并执行代码来编排多种工具、计算中间结果，并渲染支持透明、可自我校验推理的视觉产物（如框、线、图表）。为引导这一过程，我们提出了一种平衡且自适应的工具调用奖励，它在探索与效率之间取得平衡，并缓解工具滥用。有趣的是，除了原子监督所教授的预期能力之外，我们在 RL 训练中实证观察到新颖的涌现行为：CodeDance 展现出新的工具调用方式、训练数据中未曾出现的操作组合，以及跨任务迁移。这些行为无需任务特定的微调即可出现，表明存在一种面向可执行视觉推理的通用且可扩展的机制。在多个推理基准（如视觉搜索、数学、图表问答）上的大量实验表明，CodeDance 不仅持续优于模式驱动与纯文本基线，还超越了 GPT-4o 等闭源模型以及更大的开源模型。

## 1 引言

多模态大语言模型（Multimodal Large Language Models, MLLMs）进展迅速，在视觉感知与推理两方面均表现出强大能力。借助以语言为中心的思维链（Chain-of-Thought, CoT）机制（Wei et al., 2022; Brown et al., 2020），模型可以将复杂问题分解为若干中间步骤，从而在具有挑战性的任务上提升性能。然而，当扩展到视觉任务时，传统 CoT 依赖静态上下文：图像在编码进入上下文后就固定不变，模型在中间推理过程中既无法与视觉输入动态交互、也无法纳入新的观察结果（Zou et al., 2024; Chung et al., 2025）——它不能"再看一眼"图像、不能改变观察的粒度，也无法用新获取的视觉证据去复核此前的假设。这构成了一个信息瓶颈，阻碍了多轮聚焦与验证。为解决这一问题，o3 系统（OpenAI, 2025）将主动获取新信息的能力集成为推理链中的一等公民：通过多次工具调用，模型可以放大、裁剪、标注图像以产生新证据，支持对视觉输入的迭代推理，展现出强大的感知与分析能力。

**研究空白（Research gaps）。** 尽管近期模型取得了显著进展，一些根本性缺口仍未解决：

1. **纯文本模板的局限**：当前方法大多通过纯文本模板将 CoT 扩展到多模态推理，本质上仍是在"看过一次图像"后的封闭文本空间里推理，无法在推理中途纳入新的观察、细化中间步骤，或依据视觉证据验证自身推理（Ko et al., 2025; Feng et al., 2025）。
2. **闭源黑盒不可研究**：o3 仍是专有黑盒系统：其内部机制不可访问，推理过程透明度较低，其输出也无法被系统地研究或复现，学术界难以在其之上做受控的归因分析。
3. **僵硬模式化流水线**：大多数纳入视觉推理的开源系统仍局限于预定义的视觉工作流，或僵硬的、基于模式（schema）的流水线（例如预测边界框坐标用于裁剪操作）。这类流水线将"工具"窄化为少数几种固定参数形式，天然缺乏灵活性且与任务强绑定，限制了向新工具、新任务的迁移（Zheng et al., 2025; Su et al., 2025 等）。
4. **未考虑调用时机**：现有方法（Zhang et al., 2025; Zheng et al., 2025）没有考虑模型*何时*应当调用工具——工具使用策略与任务难度脱钩，导致工具调用不足（underuse，难题上不会用工具而硬猜）或过度（overuse，简单题上冗余调用拉长推理链），如图 1 所示。

因此，该领域仍然缺乏一种开放且可验证、跨工具跨任务通用的多模态推理媒介，使 MLLM 能够动态组合工具、产生中间产物，并以透明、可复现的方式自我检验其输出。表 1 的结果从侧面印证了这一需求：以 Qwen2.5-VL-7B 为基座的 CodeDance 在加入可执行代码推理后，于 CountBench、PixmoCount、V* Bench、HR-Bench 4K/8K、ChartQA、CharXiv 上分别相对提升 19.2%、53.0%、11.0%、9.0%、9.5%、1.4%、4.7%，多个项目反超 GPT-4o 与 32B/72B 级模型。弥补这一缺口对于实现任务自适应、可解释、可迁移的复杂现实任务推理至关重要。

在本工作中，我们提出 CodeDance——一个利用可执行代码作为统一媒介进行视觉推理的多模态推理框架。与以往采用固定操作模板、基于模式的流水线不同，代码使模型能够定义、组合并执行多样的视觉-符号操作，在统一、可验证的推理过程中同时产生中间产物（如裁剪区域、图表、标注）和最终答案。代码作为媒介的关键优势在于其表达力：它不仅覆盖"调用某个工具"这一动作本身，还天然承载顺序、条件、循环、数值计算等程序逻辑，因此可以表达"先定位、再逐个验证、最后聚合"这类复合策略——这是任何固定的 API 模式都难以预定义的。为赋予模型基础技能，我们精心构建了一个高质量轨迹数据集，并使用监督微调（Supervised Fine-Tuning, SFT）教授原子能力，如计数、空间定位（spatial grounding）与图像标注，从而实现"探索—反思"的迭代推理过程。在此基础之上，我们采用强化学习（Reinforcement Learning, RL）进一步增强基于工具的推理。我们识别出的一个核心挑战是**探索与选择性之间的权衡**：朴素策略往往会过度使用工具、产生不必要的步骤，或者使用不足、在需要视觉交互时未能利用。为此，我们设计了一种**难度自适应的工具奖励机制**，依据任务复杂度调节激励强度：对困难问题鼓励更长的操作链，对简单问题抑制不必要的调用。这使学习信号与多模态任务的结构对齐，产生更具适应性与透明度的推理。这些组件共同使 CodeDance 超越了僵硬的基于模式的方法，为可执行视觉推理提供了一个开放、可泛化的媒介。

**涌现行为的实证观察。** 尽管只在原子操作上训练，该框架在 RL 阶段表现出超出直接监督范围的行为，包括组合操作（例如先定位再计数）以及生成用于视觉分析的新过程代码。这些行为源自基模型的预训练知识，并由自适应奖励（而非显式指令）驱动——没有任何一个训练样本教过模型"把画框操作迁移到计数任务上"，它却在奖励结构的引导下自发出现了。这凸显了动态调用机制对于更灵活、更通用推理的可扩展性：监督只负责提供原子积木，组合方式由强化学习自行发现。

我们的贡献总结如下：

1. 我们提出 CodeDance，一个通过可执行代码作为统一媒介来规划与组合视觉-符号操作、从而"带着图像思考"的多模态智能体。为此，我们构建了一个 34K 的高质量 SFT 数据集，覆盖多样的原子代码能力（如裁剪、绘图、点标注），并额外设计了面向 RL 的难度自适应奖励机制，实现多轮推理与平衡的工具使用。
2. 我们在 10 余个多模态基准上评估 CodeDance，覆盖通用感知与复杂推理（如视觉搜索、数学推理）。在多个基准上，它优于先进的闭源模型（如 GPT-4o）和更大的开源基线（如 Qwen2.5-VL-32B），展现出强大的感知与推理能力以及广泛的泛化性。
3. 尽管只在原子操作上训练，CodeDance 在 RL 训练中实证表现出涌现行为，包括自发的新工具例程、未曾见过的操作组合，以及向新任务的跨任务迁移。这些有价值的观察凸显了本框架的可扩展性与通用性，我们在消融研究中对其进行了实证验证。

## 2 相关工作

**多模态推理与工具调用。** 在基于文本的思维链推理（Wei et al., 2022; Yao et al., 2022）的基础上，研究者将中间推理步骤扩展到多模态场景（Zheng et al., 2025; Yeo et al., 2025），包括计数（Zhang et al., 2024）、定位（Wu & Xie, 2024）、图表（Li et al., 2024）与视觉数学（Chen et al., 2025）。为增强推理能力，近期工作从三个方向集成外部工具："推理并行动"（reasoning-and-acting）框架（Yao et al., 2022, ReAct；Yang et al., 2023, MM-REACT）让模型在思考与动作之间交替；学习式 API 使用（Schick et al., 2023, Toolformer）让模型自行决定在何处插入工具调用；多模态智能体（Wu et al., 2023, Visual ChatGPT；Shen et al., 2023, HuggingGPT）则编排 OCR、检测与图像编辑器等基础模型完成复杂任务。ViperGPT（Surís et al., 2023）走得更远——将整个查询编译为可执行程序，但主要依赖固定 API 集合与较弱的代码模型。近期诸如 OpenAI o3（OpenAI, 2025）的模型将全面的工具能力直接集成到推理链中，通过在大规模 CoT 数据上进行 RL 训练获得。其他方法包括基于 RL 的工具调用（Zheng et al., 2025, DeepEyes；Su et al., 2025, Pixel Reasoner）与基于 SFT 的方法（Wang et al., 2025, Simple o3）。然而，诸如临时拼凑的操作（ad-hoc operations）、稀疏监督、有限的任务覆盖以及缺乏全面评估等挑战依然存在。与以往工作不同，我们以代码作为通用媒介，跨多样原子能力执行多模态推理——工具不再是预定义动作的枚举，而是可自由组合的程序构件。

**MLLM 的自适应思考能力。** 近期关于 LLM 自适应推理的工作探索了模型如何动态决定何时思考、思考多少（Zhang et al., 2025, AdaptThink），而非依赖固定的思维链步骤。自适应思考（Wan et al., 2025, AdapThink；Wu et al., 2025, ARM）、简洁推理（Shrivastava et al., 2025）与"学习切换"框架（Zhang et al., 2025）等方法表明，LLM 可以仅在必要时选择性地进行更深层推理，在保持精度的同时提升效率。同时，MLLM 也可以在此基础上更进一步：近期的快-慢视觉语言推理（Xiao & Gan, 2025）表明模型还能依据视觉-文本难度调整推理深度。然而，这些方法调整的是*内部推理深度*（想多久），而非*外部视觉操作*（要不要动手调工具看一眼）——二者有本质区别：前者是"想多深"，后者是"何时行动"。这一局限激发了对多模态推理中自适应工具调用的研究——MLLM 必须有效地"带着视觉输入思考"，CodeDance 的 $R_{\text{BAT}}$ 正是把"何时调用工具"本身变成 RL 的优化对象。

## 3 方法

### 3.1 总览

（图 2：本框架总览，实现可执行视觉推理并自适应地调用工具集成。）图 2 左侧展示了推理主循环——模型（策略）与沙箱（执行环境）之间的多轮交互；右侧则展示奖励设计如何沿轨迹分解为序列级与回合级两个粒度，后文将逐一展开。

**以"思考—执行—反馈"作为推理单元。** 给定一个多模态用户查询（包括文本提示与图像），策略模型（一个 MLLM）产生的 rollout 中自然语言推理与可执行代码（如裁剪、绘图）交替出现。代码在独立的沙箱中执行，所得视觉证据（如裁剪出的区域）与文本拼接，用于在下一轮细化推理或给出最终答案（例如图 2 中的"蓝色和黄色"）。以图 2 的示例走一遍完整流程：模型先在自然语言中形成假设（如"目标物体可能位于图像右侧的细小区域"），随后生成一段裁剪代码并交给沙箱执行；执行返回的裁剪图像作为新的视觉观察拼回上下文；模型据此修正或确认假设，继续下一轮，或在证据充分时输出终止动作 $a_{\text{ans}}$ 给出最终答案。整个过程里，每一次"看"都是显式的、可审计的代码行为，而非隐式的注意力刷新。

我们将一个"思考—执行—反馈"循环定义为策略模型 $\pi$ 下的最小推理单元，每一轮（turn）包含：(i) 当前查询与推理轨迹；(ii) 候选动作；(iii) 代码执行后的观察结果。形式化地，一条轨迹为：

$$\tau=\big((s_{t_{1}},a_{t_{1}},s^{\prime}_{t_{1}}),\ldots,(s_{t_{M-1}},a_{t_{M-1}},s^{\prime}_{t_{M-1}}),(s_{t_{M}},a_{\text{ans}})\big),$$

其中 $t$ 为时间步。$s_{t}=(x,o_{t},\epsilon_{t})$ 包含原始查询 $x$、累积推理轨迹 $o_{t}$ 以及解释器反馈 $\epsilon_{t}$。动作 $a_{t}$ 取自一个包含工具调用（代码片段）与终止回答的动作空间；执行代码产生观察并将状态更新为 $s^{\prime}_{t}$。通过不断迭代 $a_{t}\sim\pi(\cdot\mid s_{t})$ 直至产生最终答案或达到最大轮数预算 $M$，每一轮都成为一个可执行、可验证的推理单元。在此形式化基础上，3.2 节详述覆盖多样原子能力的高质量轨迹数据集的构建；该数据集为通过 SFT 初始化策略模型奠定基础，随后再进入 RL 阶段。

**基于可验证证据的策略优化。** 在 RL 阶段，我们需要一种能够比较多条 rollout 并据此更新模型的策略优化方法。在我们的场景中，组相对策略优化（Group Relative Policy Optimization, GRPO）（Shao et al., 2024）是一个自然的基线，因为它直接对采样轨迹间的奖励做归一化，而无需独立的价值网络。然而，标准 GRPO 为轨迹内所有 token 赋予一致的优势值（advantage），这限制了其在需要中间纠正的多轮工具推理中的效果：一条轨迹中第二轮代码执行失败、后续轮次勉强挽回，与一条全程无失败的轨迹，若最终结果相同，得到的 token 级学习信号便完全一样——失败的中间步骤得不到针对性的负反馈，成功的中间步骤也得不到针对性的正反馈，信用分配（credit assignment）粒度过粗。为此，我们在奖励设计中扩展出序列级与回合级两个组件，分别负责"整条轨迹好不好"与"这一轮执行对不对"两级信号。具体而言，每条 rollout 用一个复合奖励 $r$ 评估，它整合了结果信号与工具相关信号（另见图 2 右侧）：

$$r(\tau)=R_{\text{acc}}(\tau)+R_{\text{format}}(\tau)+R_{\text{BAT}}(\tau),$$

其中 $R_{\text{acc}}$ 表示最终答案的正确性，$R_{\text{format}}$ 强制格式合规。在我们的设计中，引入一个两级奖励 $R_{\text{BAT}}$（**平衡自适应工具调用奖励**，Reward for Balanced Adaptive Tool Calling），它依据任务难度倡导自适应的工具调用。特别地，它分解为序列级 $R_{\text{seq}}$ 与回合级 $R_{\text{turn}}$，在任务难度与逐步工具调用正确性之间取得平衡。随后，优势值 $A$ 写作：

$$A(\tau)=A_{\text{seq}}\!\big(R_{\text{acc}},R_{\text{format}},R_{\text{seq}}\big)+A_{\text{turn}}\!\big(R_{\text{turn}}\big).$$

接下来我们说明，该形式化将全局的轨迹级结果与局部的回合级执行反馈相结合，产生更自适应的工具调用。

**面向代码调用的序列级自适应奖励。** 简单地为每次成功的工具调用都给予奖励，会导致退化行为，例如工具刷分（tool spamming）或在平凡问题上的奖励欺骗（reward hacking）（见附录图 12），这可能损害推理性能（表 3 的消融研究）。究其根源，这类"按次计分"的奖励与"工具调用是否真正有助于解题"完全脱钩：只要代码能跑通就有分，与问题难度无关——这在简单题上诱导出为刷成功率而生的冗余调用，也给注释行代码这类退化输出留下可乘之机。为此，我们设计了一个**以组级准确率 $\mu_{\text{acc}}$ 为条件**的自适应奖励：当大多数 rollout 已经能正确解决任务时（表明问题相对容易、无需额外工具辅助即可解出），进一步调用受到抑制；相反，低 $\mu_{\text{acc}}$ 则鼓励更多探索。这里的 $\mu_{\text{acc}}$ 即 GRPO 为同一问题采样的一组（group）候选解答的准确率，被用作任务难度的在线估计。形式化地，序列级奖励为：

$$R_{\text{seq}}=\Big(0.5+0.5\cdot\mathbb{I}_{R_{\text{acc}}(\tau)>0}\Big)\cdot d\cdot\frac{N_{\text{succ}}(\tau)}{N_{\text{total}}(\tau)}, \tag{1}$$

$$d=\sigma\bigl(\gamma(0.5-\mu_{\text{acc}})\bigr)-\delta,\quad\sigma(z)=\frac{1}{1+e^{-z}},$$

其中 $N_{\text{succ}}(\tau)$ 与 $N_{\text{total}}(\tau)$ 分别表示轨迹 $\tau$ 中成功与总的工具调用次数，$d$ 是依赖于组准确率的缩放因子：它抑制简单查询（高 $\mu_{\text{acc}}$）上不必要工具调用的奖励，并放大困难查询（低 $\mu_{\text{acc}}$）上工具辅助解答的奖励，从而实现自适应工具调用。注意公式中的前导项：最终答案正确（$R_{\text{acc}}>0$）时基数为 $1.0$，答案错误时基数仍为 $0.5$，即答案错误的轨迹中成功的工具调用仍能获得一半权重的工具奖励。$\gamma$ 与 $\delta$ 是控制强度的超参数：更高的 $\mu_{\text{acc}}$ 会降低 $d$（抑制冗余调用），更低的 $\mu_{\text{acc}}$ 会升高 $d$（促进探索）。主实验中我们设 $\gamma=4$、$\delta=0.2$，附录 8.2 节给出这些超参数的讨论。

**精读解析：组级准确率自适应机制的具体行为。** 为便于把握该机制的实际行为，可代入默认超参数 $\gamma=4$、$\delta=0.2$ 计算几个典型情形：当组内所有 rollout 均失败（$\mu_{\text{acc}}=0$，极难题）时，$d=\sigma(2)-0.2\approx 0.68$，成功工具调用被显著放大；当 $\mu_{\text{acc}}=0.5$（中等难度）时，$d=\sigma(0)-0.2=0.30$；当 $\mu_{\text{acc}}\to 1$（几乎全对的简单题）时，$d\to\sigma(-2)-0.2\approx-0.08$，即对工具调用施加轻微的负奖励。再走一个完整的数值例子：设某难题的组级准确率 $\mu_{\text{acc}}=0.25$（8 个 rollout 中 2 个正确），则 $d=\sigma(4\times 0.25)-0.2\approx 0.53$；一条答案正确、3 次工具调用全部成功的轨迹得到 $R_{\text{seq}}=1.0\times 0.53\times\frac{3}{3}\approx 0.53$，一条答案错误、3 次中 2 次成功的轨迹得到 $R_{\text{seq}}=0.5\times 0.53\times\frac{2}{3}\approx 0.18$——工具用对了但答案错了，仍拿走约三分之一的奖励。而在 $\mu_{\text{acc}}=1.0$ 的简单题上，$d\approx-0.08$，同样那条"3 次全成功"的轨迹反而得到 $R_{\text{seq}}\approx-0.08$ 的负奖励。这里有两个值得注意的细节：其一，难度信号 $\mu_{\text{acc}}$ 并非人工标注，而是 RL 采样组（本文 rollout 数为 8，见表 4）的在线统计量，因此它天然带有小样本噪声，且会随策略能力的变化而漂移；其二，前导项 $\bigl(0.5+0.5\cdot\mathbb{I}\{R_{\text{acc}}>0\}\bigr)$ 意味着即便最终答案错误，轨迹中成功执行的工具调用仍能按一半权重获得（经 $d$ 缩放后的）正奖励——在难题（低 $\mu_{\text{acc}}$、$d>0$）上，这会奖励"工具用对了但答案错了"的轨迹；反过来，在简单题（$d<0$）上，即使答案正确，冗余的工具调用也会使 $R_{\text{seq}}$ 为负而被扣分。这一由组级准确率驱动的**双向调节**（难题奖、简单题罚）正是 $R_{\text{BAT}}$ 最具辨识度、也最值得后续工作审视的设计：它把"该不该用工具"的判断完全交给了组内准确率这一个统计量。

**回合级执行奖励。** 为惩罚失败的执行并提供密集的纠正信号，我们引入回合级奖励。对每一轮 $m$，若代码执行失败则施加即时惩罚 $r_{\text{turn},m}=-0.5$，否则为 $0$。为刻画长期影响，我们将 $r_{\text{turn},m}$ 递归地重定义为累积折扣回报：

$$R_{\text{turn}}^{m}=r_{\text{turn}}^{m}+\beta\cdot R_{\text{turn}}^{m+1},\quad A_{\text{turn}}^{m}=\frac{R_{\text{turn}}^{m}-\mu_{\text{batch}}}{\sigma_{\text{batch}}}. \tag{2}$$

这里 $R_{\text{turn}}^{m}$ 表示折扣累积的回合级回报，$\beta$ 为折扣因子，$\mu_{\text{batch}}$、$\sigma_{\text{batch}}$ 分别为 $R_{\text{turn}}$ 在批次内的均值与标准差。这一构造的语义值得细读：折扣递推意味着"第 $m$ 轮之后还会不会再失败"会影响第 $m$ 轮自身的回报——一条在早期就连续写错代码、后期才勉强挽回的轨迹，其早期 token 承载的是多轮失败惩罚的贴现和，而非与"一次失败"相同的固定罚金；批次归一化（减均值、除标准差）则把绝对惩罚强度转换为相对信号，使该优势在不同批次间可比。该回合级奖励不鼓励将信用分配给错误的中间推理步骤（即使最终答案恰好正确——"蒙对"不再是无代价的），并有助于缓解训练中的熵坍塌（entropy collapse）（图 5）。最终优势值由所得 $A_{\text{turn}}$ 与序列级优势 $A_{\text{seq}}$（来自结果级奖励，见附录）组合得到。

综合而言，组自适应的 $R_{\text{seq}}$ 评估整条轨迹的质量，而 $R_{\text{turn}}$ 评估单次工具调用的正确性。这一互补设计——我们称之为 $R_{\text{BAT}}=R_{\text{seq}}+R_{\text{turn}}$——缓解了奖励欺骗，在效率与必要探索之间取得平衡，产生更鲁棒的多模态推理策略。可以把四个奖励项各自的"防错对象"梳理为一张简明的分工表：$R_{\text{acc}}$ 守住最终正确性这一底线；$R_{\text{format}}$ 保证 `<answer>` 与代码块等输出格式可被解析与执行；$R_{\text{seq}}$（经组级准确率调制）防止简单题刷工具、难题弃工具；$R_{\text{turn}}$ 防止失败执行被"蒙对的答案"掩盖并维持探索熵。更多设计选择与结果讨论见图 5。

**方法全流程串讲（精读归纳）。** 把 3.1–3.2 节与附录实现细节串起来，CodeDance 的完整训练-推理闭环如下：第一步，数据工程（3.2 节）从公开资源出发，经弱到强过滤与多轮原子监督合成为 34K 的"推理—代码—观察"交错轨迹，并用更强模型交叉验证；第二步，SFT 冷启动在这批数据上教会模型三类原子能力与输出格式，同时以数据分布隐式示范"简单题直接答、难题调工具"；第三步，RL 阶段对每个问题采样一组（G=8）rollout，代码在隔离沙箱中执行（15 秒超时、原子事务、产物回填），随后计算复合奖励 $r(\tau)=R_{\text{acc}}+R_{\text{format}}+R_{\text{BAT}}$——其中 $R_{\text{seq}}$ 依赖组级准确率 $\mu_{\text{acc}}$ 在线判断难度、$R_{\text{turn}}$ 逐轮惩罚失败执行；第四步，序列级优势 $A_{\text{seq}}$ 广播至全轨迹 token，回合级优势 $A_{\text{turn}}^{m}$ 只作用于所属轮次，二者相加得到最终 token 级优势，驱动 GRPO 的裁剪目标更新策略；推理时模型在最多 10 轮预算内自主决定"想—写码—看结果—再想"，直至给出 `<answer>`。整个系统中没有任何针对特定基准的微调，所有能力都来自"原子监督 + 自适应奖励"的组合。

### 3.2 数据工程

在我们的设计中，缺乏高质量的、多轮的、倡导带交错代码轨迹的自适应工具调用的多模态推理数据集，仍是训练的一大障碍：现有多模态指令数据要么只有纯文本 CoT，要么只有单一裁剪操作，既没有"代码执行结果作为视觉证据回填"的格式，也没有"依难度决定是否调用工具"的策略示范。为此，我们构建了一个 34K 的冷启动数据集，其特点是：(1) 推理轨迹中包含作为视觉证据附加到训练数据里的代码执行结果——每条轨迹都是"推理文本—代码—执行观察"的交错序列，模型在训练时就能看到"我调用了工具、得到了什么、如何据此修正"的完整闭环；(2) 基于问题难度级别的自适应工具调用——对于简单问题，鼓励模型不经任何推理过程直接作答；对于困难问题，则启用基于代码的工具集成进行可执行推理。值得注意的是，这一数据侧的难度自适应策略与后续 RL 阶段的 $R_{\text{BAT}}$ 奖励在目标上一脉相承：冷启动数据先教会模型"简单题可以不调工具"的先验，RL 奖励再用显式信号强化这一行为边界。在实践中，为缓解工具刷分问题，我们的流水线遵循两步设计：

- **（i）弱到强过滤（weak-to-strong filtering）**：使用 Qwen2.5-VL-7B 对公开资源（如 SA1B（Kirillov et al., 2023）、GEOqa_plus、MMK12（Meng et al., 2025））进行自动过滤并按难度分层——弱模型先剔除平凡或低信息量样本，再由更强的模型把剩余数据分层为中等与困难两个难度集；
- **（ii）多轮原子监督（multi-turn atomic supervision）**：将困难样本分解为覆盖三类的轨迹——基础图像变换（裁剪、缩放）、数学计算（测量、代数、聚合）、开放式视觉编辑（绘图、标注等）。

每条轨迹再由一个更强的 MLLM（如 Qwen2.5-VL-72B）验证，以交叉核验正确性。查询、代码与响应以交错序列的形式嵌入训练数据（原文此处附有格式示例）。这些轨迹为用于 SFT 冷启动的原子技能提供了可验证的监督。附录 7.1 节提供了轨迹合成、过滤与 SFT 数据代码集成的完整配方，以及 RL 训练的补充示例。值得指出的是，34K 的规模在同类工作中并不算大，作者将其有效性归因于轨迹质量（多裁判交叉验证）与难度结构（简单/困难分层）而非数量堆砌——这与附录中"以显著更少的训练数据获得有竞争力的'带着图像思考'能力"的表述相一致。

### 4.1 视觉推理任务

如表 1 所示，CodeDance 在计数、视觉搜索与图表理解等多样的视觉推理基准上取得了强劲结果。值得注意的是，它在计数（CountBench 91.2、PixmoCount 77.1）与 ChartQA（87.5）上取得最优性能，大幅超越基线，甚至超过更大的模型。与同属工具集成阵营的三个 7B 基线相比，CodeDance 的优势同样清晰：Pixel Reasoner-7B 只报告了 V*/HR-Bench 三项，Thyme-VL-7B 在多数基准上落后 1–2 分以上，DeepEyes-7B† 则呈"单项突出、整体不均"的形态（V* Bench 高达 90.4，但 ChartQA 仅 78.2、且未报告 CharXiv）。这些提升凸显了可执行代码作为推理媒介的优势：通过将细粒度视觉分析委托给基于代码的工具，它超越了基座模型的原始感知容量，取得了仅靠模型规模扩展无法实现的收益，尤其是在感知密集型任务上。相对基座 Qwen2.5-VL-7B，各基准分别提升 19.2%、53.0%、11.0%、9.0%、9.5%、1.4% 与 4.7%（相对提升）。精读对照表 1 还可看到一个更完整的图景：CodeDance 并非在每个单项上都居首——例如 V* Bench 上复现的 DeepEyes-7B† 达 90.4（CodeDance 为 84.8）、CountBench 上 Qwen2.5-VL-72B 达 93.6、CharXiv 上 Qwen2.5-VL-72B 达 49.7——但其优势在于以 7B 规模在全部七个基准上同时保持第一梯队水平：PixmoCount 77.1 大幅领先第二名 Llava-OneVision-72B 的 60.7 达 16.4 分，HR-Bench 8K 的 72.3 也超过了 78B 级的 InternVL3-78B（67.3）与 Qwen2.5-VL-32B（71.6），体现了较强的综合泛化能力。

### 4.2 数学推理任务

在数学推理上，CodeDance 相对开源基线取得一致提升（见表 2）。例如，它在 MathVision 上将准确率从 25.0 提升至 29.6（+18.4%），在 WeMath 上从 35.4 提升至 39.6（+11.9%），同时在其他基准上保持有竞争力的结果（MathVista 70.3 略高于 DeepEyes 的 70.1；MathVerse 46.8 略低于 DeepEyes 的 47.3；MathVision 与专门的推理模型 R1-Onevision-7B 的 29.9 基本持平；相对 GPT-4o，CodeDance 在 MathVision、MathVista、MathVerse 上分别相差 -6.9、+6.9、+11.5 分，其中 MathVista 与 MathVerse 两项反超）。这些任务需要精确的符号操作与逐步计算，而这天然由可执行代码支持。通过将中间步骤外化为可验证的脚本，CodeDance 展现出比仅依赖内部近似更强的准确性与可靠性。

### 4.3 关键发现：RL 训练中的涌现行为

（图 3：RL 过程中涌现的有趣推理轨迹。这些行为在 SFT 数据中并不存在，源自被 RL 进一步塑造的预训练知识，反映了我们自适应工具调用的设计。这些涌现模式启发我们在图 4 中开展扩展研究，进一步检验这些能力是否随更大的数据、更长的训练和更大的模型而增强。）

在整个 RL 过程中，我们观察到超越 SFT 所提供原子监督的新颖且令人惊讶的实证发现（见图 3）。这些发现指向代码作为通用推理媒介的可扩展性，我们在图 4 中对其潜力进行了实证研究。以下依次呈现三类涌现行为。

**跨领域工具迁移（cross-domain tool transfer）。** 我们在 CodeDance 中观察到一种涌现的泛化能力：为特定任务定义的视觉操作可以在其他情境中被重新利用。例如，边界框操作在 SFT 数据中最初是为图表任务中高亮特定结果而设计的；然而模型在 RL 训练中展现出将该操作适配到计数任务上的能力：如图 3A 所示，MLLM 助手首先通过绘制边界框定位所有候选目标，然后验证每次定位的正确性，随后推导出最终计数。更多工具迁移轨迹见图 14。这种行为表明，任务特定的视觉操作并非僵硬地绑定于其原始用途，而是可以灵活泛化以支持更广泛的多模态推理场景；边界框等视觉操作可以充当**通用推理原语（reasoning primitives）**，成为跨异构任务可迁移的构建模块。"推理原语"这一视角颇具启发：与其为每个任务设计专用工具集，不如提供一组可跨任务复用的基本视觉操作、让策略层自行组合——这也部分解释了为何 CodeDance 的监督面虽只有三类原子操作，可覆盖的任务面却很宽。

**已学能力的新颖工具组合（novel tool composition）。** 尽管在 SFT 数据的整理与收集阶段，每个任务都被限制为单一预定义工具或编码操作，我们观察到后训练之后，模型发展出组合多个原子操作以应对超出训练覆盖范围的更复杂任务的能力：在图 3B 中，为验证房子的颜色，MLLM 助手首先施加"打点"操作检查房子位置的正确性，然后使用带放大的裁剪聚焦细粒度细节。类似地，附录图 15 展示了将边界框绘制与裁剪组合起来聚焦并解决图表推理任务的示例。这些观察凸显了新颖工具组合的涌现：基本视觉操作被灵活组合，形成更高层的推理策略。

**激发未见能力的新颖涌现（incentivizing emergence of novel unseen capabilities）。** 有趣的是，我们还发现模型表现出生成 SFT 数据中未显式定义的工具代码的潜力。这些代码似乎取自模型的预训练知识，并在后训练阶段被偶发性激活。例如，当被要求数出图中耳机的数量时（图 3C），MLLM 并不直接回答一个数字，而是尝试编写带 OpenCV 函数的 Python 代码（例如用 `cv2.rectangle` 叠加网格以便更好地可视化）。这一观察表明，除了复现 SFT 定义的行为之外，模型还尝试复用并改编预训练能力（如复杂 OpenCV 操作）来支持推理任务，显示出更灵活工具使用的潜在可能。

值得强调的是，上述三类行为均未经过任何任务特定的微调：它们或从其他任务迁移既有操作（第一类）、或组合训练中只以单工具形式出现的能力（第二类）、或干脆调用预训练语料中未被 SFT 数据触达的代码知识（第三类），共同支撑了"代码是可扩展的通用推理媒介"这一核心论断，也直接引出了 4.4 节沿四个维度的扩展研究。

### 4.4 消融研究

**奖励设计的验证。** 我们比较了三种引导工具使用的奖励设计（表 3）：

1. **GRPO 奖励（结果级奖励）**：只关注最终答案正确性。虽然它缩短了交互轮数，但不鼓励使用工具，在复杂任务上表现欠佳。
2. **DeepEyes 奖励**：在答案正确的前提下，为每次成功的工具执行都授予正信号。这虽然鼓励了探索，但也导致在平凡问题上过度使用工具，轮数增加却没有稳定的准确率收益（定性示例见附录图 12）。
3. **我们的自适应工具调用奖励 $R_{\text{BAT}}$**：通过惩罚冗余调用、奖励选择性高影响的交互，在两个极端之间取得平衡——简单题上组级准确率高、缩放因子 $d$ 转为负值从而抑制调用，难题上 $d$ 为正放大工具收益，再配合回合级的失败执行惩罚，形成"按需调用"的闭环。

如表 3 所示，结果级 GRPO 导致工具利用不足，DeepEyes 奖励则在无可靠准确率提升的情况下虚增轮数（平均 2.26 轮 vs. CodeDance 的 1.38 轮）。逐项精读几个典型格子可以更清楚地看到三种奖励的行为差异：在 CountBench 上，DeepEyes 奖励把平均轮数从 1.22 拉高到 2.35，准确率反而从 89.0 掉到 83.1——这正是"为调工具而调工具"的代价；而完整 $R_{\text{BAT}}$ 以恰好 1.00 轮（即几乎不冗余调用）拿到全场最高的 91.2。在 Pixmo 上，$R_{\text{BAT}}$ 去掉回合级组件的版本虽然取得最高单点 78.8，但其执行成功率骤降至 0.91（其余设置均在 0.96–0.99 之间），说明没有失败执行的即时惩罚时，模型会容忍更多跑不通的代码；加回回合级奖励后成功率回升至 0.99，同时保住 77.1 的准确率。总体而言，完整的 $R_{\text{BAT}}$ 在避免不必要工具使用的同时取得最佳整体准确率（平均 68.1），持续超越两种基线奖励。

**计算预算扩展的验证。** 受图 3 中涌现行为的启发，我们进一步检验 CodeDance 是否能沿四个维度持续受益于扩展（见图 4）。（图 4：在四个维度上扩展计算预算：SFT 数据集规模、模型容量、推理时的最大轮数与 RL 步数。）具体而言：（i）SFT 训练数据集规模，涵盖数学推理（MathVision、MathVerse、MathVista）、视觉搜索（V*、HR 4K、HR 8K）与通用（ChartQA、MMVet、MMStar）——我们一致观察到将 SFT 数据集从 5K 扩大到 34K 带来稳定的准确率提升，表明工具选择与符号规划均受益于更广的覆盖；（ii）模型容量从 3B 增至 7B 显著提升计数与搜索等推理基准，其中 CodeDance-3B 甚至优于某个更强的 7B 模型；（iii）将 RL 训练延长至 240 步仍在继续提升准确率而无过拟合，这得益于我们的奖励设计 $R_{\text{BAT}}$；（iv）增加推理轮数预算——尽管 RL 训练设置的最大轮数为 6，我们观察到推理时允许更多轮（10）能继续提升推理性能；实验中模型即使超过 6 轮仍获得额外收益（$0.3\%$），表明所学策略能泛化到更长的推理视野。

**推理熵与准确率的实证研究。**（图 5：模型生成的熵与验证准确率。）在图 5 中，我们评估了纳入回合级奖励（$R_{\text{turn}}$）对训练动力学与泛化的影响，主要研究的基准包括视觉搜索（V* Bench）、数学推理（MathVista、MathVerse、MathVision）与计数（PixmoCount、CountBench）。(a) **熵**：若没有 $R_{\text{turn}}$，策略熵会迅速坍塌，因为有缺陷的中间步骤仍可能导向正确的最终答案，从而强化"捷径"并限制探索（Yu et al., 2025, DAPO）——在工具集成场景中这一点尤其危险：模型可能过早固化成"从不调工具"或"只会一种固定调用模式"的退化解；有了 $R_{\text{turn}}$，中间惩罚延缓了坍塌、维持了探索。(b) **验证准确率**：额外的纠正信号防止了过早收敛，并转化为持续更高的准确率，表明局部（回合级）反馈能够改善全局泛化。这一结果与 4.4 节的消融互相印证：回合级奖励的价值不仅在于惩罚坏代码，更在于维持策略多样性，为后续的涌现行为（4.3 节）保留了探索空间。

综合本节三项研究，可以得出一致的结论：CodeDance 的收益并非来自单一组件，而是"序列级难度自适应 + 回合级执行纠错"两股信号的配合——前者决定工具激励的总量，后者决定这些激励能否落在真正正确的执行上；同时，四个维度上的扩展实验表明该配方没有触及性能天花板。

## 5 讨论

我们提出了 CodeDance，一个任务感知、难度自适应、使用可执行代码进行工具集成视觉推理的 MLLM。通过允许模型定义并执行代码，CodeDance 实现了带有可解释中间证据的灵活推理，同时促进自适应的工具调用、抑制工具刷分。在 RL 过程中，CodeDance 表现出超越监督技能的涌现行为，包括新颖的工具例程、组合式策略与跨领域迁移。我们进一步验证了其可扩展性，观察到随计算预算增加而出现的清晰且一致的收益。即便在 7B 规模，CodeDance 也在多样基准上取得有竞争力的表现，凸显了基于代码、难度自适应的推理是多模态与智能体 AI 的一种可扩展、可迁移的范式。

从精读视角复盘，CodeDance 的设计可以概括为三根支柱的合力：**代码媒介**提供了表达任意视觉-符号策略的统一接口，**冷启动数据**以"依难度决定是否调工具"的示范锚定了调用先验，**自适应奖励 $R_{\text{BAT}}$** 则在 RL 中动态校准"探索 vs. 效率"的边界。三者缺一不可——没有代码媒介，自适应无从谈起；没有数据先验，RL 会从噪声起步；没有奖励校准，探索要么塌缩为工具弃用、要么膨胀为工具刷分。7B 规模上的结果与涌现行为共同表明：把"何时用工具、怎么用工具"交给模型在奖励信号下自行探索，是一条可扩展的路线。

**代码沙箱实现（6.2 节）**：（图 6：奖励设计 $R_{\text{BAT}}$ 与代码沙箱（即执行环境）的交互。）为安全执行模型生成的程序，所有 Python 代码在内部沙箱环境中运行。每次执行实例分配独立的工作目录与专用的变量/函数/导入命名空间；多模态任务的输入图像存储在对应的临时目录中，仅在该实例内可见。这一设计避免了并发 rollout 之间的干扰，并将状态限制在单条轨迹内。在运行用户代码前，沙箱禁用少量可能危及稳定性的 API（如阻断用户输入、直接的进程终止），并将每次执行视为原子事务：若某次运行失败或被中断，部分更新将被丢弃，实例的逻辑状态回退到最后一次成功的步骤。沙箱还强制执行严格的单次调用墙上时间限制（默认 15 秒），超时则中止当前执行并返回超时状态。最后，沙箱集中捕获结构化的 stdout/stderr 日志以及常见绘图库（matplotlib、PIL）产生的图形输出，作为文本与视觉观察反馈给模型。奖励设计 $R_{\text{BAT}}$ 与代码沙箱的交互示意见图 6。精读注：沙箱的这些设计并非单纯的工程细节，而是奖励计算的承重墙——"执行成功/失败"的二值判定直接喂给 $R_{\text{turn}}$ 的逐轮惩罚，捕获的图形产物则决定模型下一轮能看到什么证据；隔离与原子事务保证了并发 rollout 之间互不污染，否则组级准确率 $\mu_{\text{acc}}$ 这一难度信号本身就会被串扰的执行状态所污染。

**标准 GRPO 的实现（6.3 节）**：GRPO（Shao et al., 2024）在多轮工具调用智能体与"带着图像思考"系统中已展现出强有效性。与 PPO（Schulman et al., 2017）不同，GRPO 无需独立的价值网络，而是直接从 $G$ 个采样解答的归一化奖励中计算优势。对于从任务数据集 $\mathcal{Q}$ 中采样的问题 $q$，一组 $G$ 个候选解 $\tau_{i}\sim\pi_{\theta_{\text{old}}}$ 被 rollout 并用奖励函数 $r(\cdot)$ 评估。在 PPO 的裁剪代理目标基础上，目标函数写作：

$$\mathcal{J}_{\text{GRPO}}(\theta)=\mathbb{E}_{q\sim\mathcal{Q},\,\{\tau_{i}\}_{i=1}^{G}\sim\pi_{\theta_{\text{old}}}(\cdot\mid q)}\Bigg[\frac{1}{G}\sum_{i=1}^{G}\frac{1}{|\tau_{i}|}\sum_{t=1}^{|\tau_{i}|}\min\Big(r_{i,t}A_{i},\ \text{clip}(r_{i,t},1-\varepsilon,1+\varepsilon)A_{i}\Big)\Bigg], \tag{3}$$

其中 $r_{i,t}=\frac{\pi_{\theta}(\tau_{i,t}\mid q,\tau_{i,<t})}{\pi_{\theta_{\text{old}}}(\tau_{i,t}\mid q,\tau_{i,<t})}$，默认 $\varepsilon=0.2$，$\text{clip}(\cdot)$ 为稳定性裁剪算子（为简洁起见省略 KL 惩罚）。组内归一化奖励随后定义解答 $\tau_{i}$ 的优势：

$$A_{i}=\frac{r(\tau_{i})-\text{mean}(\{r(\tau_{j})\}_{j=1}^{G})}{\text{std}(\{r(\tau_{j})\}_{j=1}^{G})}. \tag{4}$$

我们基本遵循 GRPO 的原始实现来计算结果驱动优势 $A_{\text{seq}}$。精读注：GRPO 用"组内相对表现"替代了价值网络——一条 rollout 的优劣只看它与同组同伴的相对位置；而 CodeDance 对这组采样信息做了双重利用：一方面按标准 GRPO 用组内均值/方差归一化奖励得到优势，另一方面把组内准确率显式提取为 $\mu_{\text{acc}}$，作为任务难度的在线估计去驱动 $R_{\text{seq}}$ 的缩放因子 $d$——同一批 rollout 的统计量同时服务于"归一化"与"难度自适应"两个用途，无需任何额外的难度标注或评估器。

### A2. 数据工程细节（附录第 7 节）

**数据合成背景**：高性能 MLLM 需要大量带详细推理轨迹的指令跟随训练数据。近期方法或用固定模板转换既有数据集（Wei et al., 2021; Dai et al., 2023），或从强教师模型蒸馏知识（Chen et al., 2024; Zhang et al., 2025, Thyme; Wang et al., 2025, Simple o3），并聚焦于发展特定能力，如视觉中心推理（Lan et al., 2024, Text4Seg）与视觉线索辅助的数学求解（Gao et al., 2023, G-LLaVA；Chen et al., 2025, MINT-cot）。但这些方法存在局限：(i) 往往缺乏基于工具的验证机制——蒸馏出的中间步骤是否真的"看过"图像无从核验；(ii) 视觉操作通常局限于裁剪、放大等固定模式。相比之下，本文以覆盖广泛原子视觉操作的完整推理轨迹与工具/代码辅助响应来合成并整理训练数据，采用增强的过程监督（多裁判过滤与一致性验证），以显著更少的训练数据获得有竞争力的"带着图像思考"能力。

**轨迹合成的数据来源**：数学推理（MMK12（Meng et al., 2025）、ReTool（Feng et al., 2025））、表格数据（ChartQAPro（Masry et al., 2025）、chartgemma（Masry et al., 2024））、自然图像（SA1B（Kirillov et al., 2023））、通用数据（Mulberry（Yao et al., 2024））。RL 训练数据主要来自 DeepEyes（Zheng et al., 2025）、SA1B 与 PixmoCount 训练集。可以看出 SFT 与 RL 两个阶段使用了不同的数据来源组合：SFT 侧覆盖数学、图表、自然图像与通用四类，RL 侧则集中于 DeepEyes、SA1B 与 PixmoCount 训练集。

### A3. 补充实证研究（附录第 8 节）

**序列级/回合级奖励的可视化（8.1 节，图 6）**：每个查询通过"推理—代码—响应"（Reasoning–Code–Response）轮次序列求解，代码在共享沙箱中执行以便跨轮复用中间变量与视觉产物。整条轨迹 $\tau$ 完成后，序列级奖励 $R_{\text{seq}}$ 由最终答案正确性与全局工具使用统计 $(N_{\text{succ}}(\tau),N_{\text{total}}(\tau),\mu_{\text{acc}})$ 计算，对应的序列级优势 $A_{\text{seq}}$ 广播到轨迹中的所有 token（图中底部绿色条），提供依任务难度自适应地鼓励或抑制整体工具使用的结果级学习信号。回合级组件（图中红色虚线框内）则由每轮 $m$ 的执行结果计算：失败执行获得即时负惩罚 $r_{\text{turn},m}<0$，成功或无代码轮次为 $0$（图中以斜线阴影表示零回合级信号）；这些逐轮惩罚累积为折扣回报 $G_{\text{turn}}^{m}$ 并归一化为优势 $A_{\text{turn}}^{m}$，且只分配给该轮自身的 token（图中着色分段）。最终的逐 token 优势由全局 $A_{\text{seq}}$ 与所属轮的局部 $A_{\text{turn}}^{m}$ 组合而得——这正是式 $A(\tau)=A_{\text{seq}}+A_{\text{turn}}$ 在 token 粒度上的落地方式。

**$R_{\text{BAT}}$ 超参数的敏感性（8.2 节）**：序列级组件重述为：

$$R_{\text{seq}}(\tau)=\Bigl(0.5+0.5\cdot\mathbf{1}\{R_{\text{acc}}(\tau)>0\}\Bigr)\,d(\mu_{\text{acc}})\,\frac{N_{\text{succ}}(\tau)}{N_{\text{total}}(\tau)}, \tag{5}$$

其中 $d(\mu_{\text{acc}})=\sigma\!\bigl(\gamma(0.5-\mu_{\text{acc}})\bigr)-\delta$，$\mu_{\text{acc}}\in[0,1]$ 为组级准确率，$\sigma(z)=1/(1+e^{-z})$ 为逻辑函数，$(\gamma,\delta)$ 控制组准确率对工具调用激励的调节强度。附录对各项的含义作了完整拆解：$\frac{N_{\text{succ}}(\tau)}{N_{\text{total}}(\tau)}$ 度量轨迹内工具执行的成功比例；前导项 $\bigl(0.5+0.5\cdot\mathbf{1}\{R_{\text{acc}}(\tau)>0\}\bigr)$ 依最终答案正确性切换基数权重；缩放项 $d(\mu_{\text{acc}})$ 则承载难度自适应。直觉上，$d(\mu_{\text{acc}})$ 随 $\mu_{\text{acc}}$ 增大而减小：当组内普遍解不出（低 $\mu_{\text{acc}}$）时放大成功工具调用的价值，当组内已经表现良好（高 $\mu_{\text{acc}}$）时抑制不必要的调用。$\gamma$ 调节过渡的陡峭程度，$\delta$ 平移基线并决定高准确率区间是否出现抑制，$\beta$ 是 $R_{\text{turn}}$ 中逐轮惩罚的折扣因子。主实验设置为 $\gamma=4$、$\delta=0.2$、$\beta=0.2$，敏感性结果汇总于图 10。

**$d(\mu_{\text{acc}})$ 的有效范围与界限（8.2.2 节）**：由 $\sigma(\cdot)\in(0,1)$ 与 $\mu_{\text{acc}}\in[0,1]$ 可得缩放项的确定性界限：

$$-\delta<d(\mu_{\text{acc}})<1-\delta.$$

在默认配置下即 $d\in(-0.2,0.8)$：正向下最多放大到约 0.68（$\mu_{\text{acc}}=0$ 时），负向下最深约 $-0.08$（$\mu_{\text{acc}}\to 1$ 时），量级上的不对称本身就是设计意图的体现——鼓励是主旋律，抑制只是轻推。

重要的是，$d$ 取负值是有意为之而非病态：它只在组级准确率 $\mu_{\text{acc}}$ 足够高时出现，用于抑制简单查询上不必要的工具调用。$d$ 的符号翻转发生在唯一阈值：

$$\mu_{\text{acc}}^{\star}=0.5-\frac{1}{\gamma}\,\sigma^{-1}(\delta),\quad\text{where }\sigma^{-1}(u)=\log\frac{u}{1-u},$$

取 $\gamma=4$、$\delta=0.2$ 时，翻转点约为

$$\mu_{\text{acc}}^{\star}\approx 0.5+\frac{1}{4}\log\frac{1-0.2}{0.2}\approx 0.85,$$

即只有当组内大多数 rollout 已经正确时，$d$ 才略微为负；在其余所有区间（中等或低 $\mu_{\text{acc}}$），$d>0$ 且 $R_{\text{BAT}}$ 会增大成功工具调用的相对价值。结合针对失败执行的逐轮惩罚 $R_{\text{turn}}$，该设计防止了退化的工具刷分或工具弃用行为：简单任务上负的 $d$ 抑制额外调用，困难任务上正的 $d$ 放大正确执行工具的收益。

**$(\gamma,\delta)$ 的超参数消融（8.2.3 节，图 10）**：（图 10：三种 $(\gamma,\delta)$ 配置下 $R_{\text{BAT}}$ 的训练动态：在 RL 基准并集上随训练步数绘制准确率（上）与平均推理轮数（下）。）作者训练三种设置 $(4,0.2)$、$(4,0.0)$ 与 $(5,0.2)$ 并监控训练准确率与每例平均工具调用次数，从而实现两组受控对比：(i) 固定 $\delta=0.2$ 比较 $\gamma\in\{4,5\}$；(ii) 固定 $\gamma=4$、通过 $\delta\in\{0,0.2\}$ 隔离"高组级准确率时是否启用抑制"这一单一因素。图 10 在 RL 基准并集上绘制了训练步数上的准确率（上）与平均推理轮数（下）。经验上，$\gamma$ 对训练准确率影响很小（$\gamma\in\{4,5\}$ 主要平滑 $d(\mu_{\text{acc}})$ 中的过渡），而设 $\delta=0$ 会移除对高 $\mu_{\text{acc}}$ 组的抑制，导致工具调用次数随训练稳定攀升、准确率却仅有边际提升，即典型的工具过度使用。默认选择 $(4,0.2)$ 在保持高准确率的同时约束了不必要的工具使用。

**推理深度分析（8.3 节，图 11）**：（图 11：推理深度与任务难度的关系。）我们的策略使推理深度与任务难度对齐——以 GPT-4o 准确率度量任务难度并绘制其与轮数的关系，验证了更难的问题确实诱发更长的推理轮数，而简单问题则较早终止。这与图 1 的动机相互印证：模型确实学到了"按需调用工具"，而非对全部任务施加同一种调用强度。

### A4. 补充定性结果（附录第 9 节）

**朴素工具调用奖励下的奖励欺骗案例（图 12）**：（图 12：出现奖励欺骗的推理轨迹示例（对代码生成使用 DeepEyes 风格的工具奖励）——MLLM 生成仅含注释行的代码来钻奖励空子，实际并未执行。）简单强化每次成功工具调用的朴素奖励方案容易诱发奖励欺骗（reward hacking）——模型钻奖励设计的空子而非真正改进推理。图 12 展示了一个使用 DeepEyes 风格工具奖励训练代码生成时的典型案例：模型生成仅由注释行组成的代码，实际并未执行任何操作，却依然满足"工具调用成功"的表面奖励信号。这类行为人为虚高了工具成功指标，对解决任务毫无实际贡献，从而误导训练、损害推理质量。这正是 $R_{\text{BAT}}$ 在设计上引入组级准确率调制与回合级执行验证的动机之一：注释行代码在 $R_{\text{turn}}$ 的执行成败判定下无处遁形，而 $R_{\text{seq}}$ 又要求工具调用真正与"解出难题"相关联才值得奖励。

**失败案例（9.1 节，图 13）**：（图 13：实验中发现的失败案例。A：模型执行了错误的裁剪；B：右边缘的人物被部分遮挡，因而难以计数。）尽管模型在各基准上表现具备竞争力，仍观察到若干失败模式。案例 A——当模型误判目标区域或视觉线索细微时，可能出现不精确或次优的裁剪：模型围绕人物选择了过大的边界框，导致裁剪图像混杂多个物体；虽然最终回答正确，但工具调用明显失准。案例 B——模型可能遗漏复杂场景中被部分遮挡的物体：模型正确识别并标记了可见的个体，但未考虑是否还有人员被遮挡，导致最终计数不完整。这些案例凸显了在模糊或杂乱视觉条件下精确定位与鲁棒多步验证仍存挑战。

### A5. 讨论的延伸（附录第 10 节）

**为什么选择基于代码的工具使用，而非 API 式调用？** 采用 Python 代码作为工具使用媒介，是因为它提供了通用且可组合的接口。与固定 API 模式不同，代码天然同时支持工具调用与程序逻辑（顺序、条件、循环、数值计算）。这一更丰富的接口让模型能灵活定义与组合操作，并产生可系统检查的透明、可验证执行痕迹。实践中代码也让扩展变得简单：新增工具只需暴露其 API，无需重新设计模板、重训连接器或构造复杂提示。精读注：这一点也与 4.3 节的涌现行为互为因果——正因接口是图灵完备的程序语言而非有限的动作枚举，模型才能把预训练中沉淀的 OpenCV、PIL 等代码知识"就地"转化为新的视觉操作；若接口是固定的 N 个 API，这类迁移与组合在结构上就不可能发生。

**为什么选择单一稠密模型，而非智能体流水线？** 统一的稠密模型相比模块化智能体工作流有若干实践优势：(1) 通过端到端接口学习，避免多组件间的误差传播；(2) 推理与工具编排单次前向即完成，延迟与计算成本更低；(3) 更鲁棒，性能不依赖于各子模块的可靠性；(4) 拥有统一的优化目标，而智能体系统往往需要额外单独调优的策略或连接器。此外，受现实算力约束，本文实验主要在 7B 规模（Qwen2.5-VL-7B）上进行，且已观察到可喜效果：在通用理解与复杂推理基准上取得一致提升，并涌现出新的行为（如新颖工具使用、把原子技能组合到新任务的工具组合）；这些实证观察在单一稠密模型内更易随规模放大，而智能体流水线引入的众多交互模块会使训练与部署都复杂化。总体而言，本设计偏向简洁、高效与可扩展，是未来进展更实用的基础。

### A6. 更广泛的影响（附录第 11 节）

本工作通过采用可执行代码作为工具使用的统一媒介，有助于构建更透明、更可验证的多模态推理系统。生成可解释轨迹与中间产物的能力，可惠及问责性与可审计性至关重要的应用，如科学分析与教育——教师或审计者可以逐步检查模型"看了哪里、算了什么、为何如此裁剪"，这在黑盒端到端系统中几乎不可能。与此同时，代码生成模型也带来风险：恶意用户可能将其用于不安全的自动化，生成的视觉产物也可能被滥用以误导或操纵（例如伪造看似可信的"证据"图像）。为缓解这些担忧，建议为此类系统配备适当防护，包括安全过滤、使用约束与负责任的部署实践，从而在最小化滥用风险的同时实现可执行视觉推理的收益。

### A7. 局限与未来工作（附录第 12 节）

**局限**：首先，对高质量合成轨迹的依赖意味着某些真实世界推理模式可能未被充分代表，可能限制开放域场景下的鲁棒性——合成-真实分布差距始终是数据驱动方法的隐忧。其次，尽管代码提供了通用接口，扩展到更丰富的模态（如音频）或领域专用工具（如医疗应用）仍需额外工程。最后，受算力约束，评估主要在 7B 规模进行；更大规模下涌现行为的可扩展性仍有待系统检验。不过，初步实验已显示出扩大模型容量与计算资源时的可喜趋势。

**未来工作**：本框架展示了多模态推理模型通过可执行代码支持自然对话与无缝、主动的工具使用，从而实现更高级问题求解的潜力。展望未来，我们预期"带着图像思考"的能力将超越视觉模态与固定模式，促进新工具的发现与更通用、高效的自发工具组合，最终为跨领域多功能、自适应的多模态智能体铺平道路。换言之，本文验证的核心命题——"监督提供原子积木、自适应奖励引导组合"——并不绑定于视觉这一种模态；当工具空间扩展到音频、代码检索乃至领域专用 API 时，同一配方是否仍然成立，是后续工作最值得检验的方向。

## 创新点提炼

1. **可执行代码作为视觉推理的统一通用媒介**：区别于固定 schema 的工具调用（如仅预测边界框坐标用于裁剪），CodeDance 让模型自主定义、组合并执行代码来编排多工具、计算中间结果并渲染可自检的视觉产物（框、线、图表），使推理过程透明、可验证、可复现；由于代码同时承载调用与程序逻辑（顺序、条件、循环、数值计算），"先定位、再验证、后聚合"这类复合策略无需预定义即可表达，且新增工具只需暴露 API 即可扩展。
2. **基于组级准确率的难度自适应两级奖励 $R_{\text{BAT}}$**：序列级 $R_{\text{seq}}$ 以 GRPO 组内准确率 $\mu_{\text{acc}}$ 为在线难度信号，通过缩放因子 $d=\sigma(\gamma(0.5-\mu_{\text{acc}}))-\delta$（界于 $(-\delta,1-\delta)$）动态调节工具激励——难题放大工具收益（$d>0$）、简单题抑制冗余调用（$\mu_{\text{acc}}^\star\approx0.85$ 后 $d<0$，有意设计为负）；回合级 $R_{\text{turn}}$ 对执行失败施加即时惩罚 $-0.5$ 并按折扣 $\beta$ 累积、批次归一化为仅作用于该轮 token 的优势，提供密集纠错信号并缓解熵坍塌与奖励欺骗（如注释行代码刷分）。
3. **面向自适应工具调用的冷启动数据工程**：构建 34K 高质量多轮"推理—代码—观察"交错轨迹数据集，采用弱到强难度分层过滤与三类原子监督（图像变换、数学计算、开放式视觉编辑），并由更强模型（Qwen2.5-VL-72B）交叉验证；数据本身即按难度决定是否调用工具（简单题直接作答、难题启用代码推理），从源头抑制工具刷分，并与 $R_{\text{BAT}}$ 的目标一脉相承。
4. **RL 阶段的涌现行为及其系统验证**：仅经原子操作监督的模型在 RL 中自发涌现跨任务工具迁移（如把图表任务的边界框操作迁移到计数）、未曾见过的新颖工具组合（打点+裁剪、画框+裁剪）以及 SFT 未定义的新工具代码（如 OpenCV 的 cv2.rectangle 叠加网格），且这些行为经四维度扩展实验（SFT 数据 5K→34K、模型 3B→7B、RL 至 240 步、推理轮数 6→10）证实随计算预算持续增强，凸显"监督给积木、奖励促组合"的可扩展机制。
5. **7B 规模上的强性能与全面评测**：在计数、视觉搜索、图表、数学等 10 余个基准上，CodeDance-7B 超越 GPT-4o、Qwen2.5-VL-32B 等更大模型及 DeepEyes、Pixel Reasoner、Thyme 等工具集成基线（如 PixmoCount 77.1、相对提升 53.0%），并在全部七项视觉基准上以 7B 规模保持第一梯队；消融研究进一步验证了自适应奖励相对结果级 GRPO 奖励与 DeepEyes 奖励在"准确率—轮数—执行成功率"三者上的综合优势（平均 68.1 / 1.38 轮 / 0.99）。
