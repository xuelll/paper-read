## 一句话核心总结

PyVision 是一个交互式、多轮的智能体视觉推理框架：它不向多模态大语言模型（MLLM）提供任何预定义的视觉工具集，而仅以 Python 及其科学计算/视觉库生态作为"原子积木"，让模型在推理时针对当前任务自主"发明"工具——生成、执行并迭代精炼 Python 代码——并配套进程隔离、跨轮状态持久化的隔离运行时；作者进一步通过嵌入聚类归纳出工具分类学（taxonomy），揭示不同任务与领域激发的差异化工具使用模式，实证动态工具稳定放大后端模型的既有优势（GPT-4.1 在 V\* 上 +7.8%、Claude-4.0-Sonnet 在 VLMsAreBlind-mini 上 +31.1%），标志着从"使用工具"到"发明工具"的智能体视觉推理范式转变。

## 摘要

LLM 正日益被部署为智能体（agent）——即能够规划、推理并动态调用外部工具的系统。然而在视觉推理领域，既有方法大多仍受限于预定义的工作流与静态工具集。在本报告中，我们提出 **PyVision**——一个交互式、多轮的框架，使 MLLM 能够自主生成、执行并精炼面向当前任务量身定制的基于 Python 的工具，从而解锁灵活且可解释的问题求解。我们为 PyVision 所创造的工具建立了一个分类体系，并分析了其在一系列多样化基准上的使用情况。定量上，PyVision 带来了一致的性能增益：在 V\* 上使 GPT-4.1 提升 +7.8%，在 VLMsAreBlind-mini 上使 Claude-4.0-Sonnet 提升 +31.1%。这些结果指向一个更宏大的转变：动态工具使模型不只是使用工具，而是发明工具，向着更具智能体性的视觉推理迈进。

## 1 引言

能够自主规划并执行任务的 AI 智能体理念，正在现代 AI 研究中迅速崛起。最初为文本生成而构建的大语言模型（LLM），已快速演化为称职的智能体：它们能制定计划、与环境交互、调用外部工具或函数，以最少的人工监督解决复杂问题 (OpenAI, 2025; MiniMax, 2025; Manus, 2025; Luo et al., 2025; Qiu et al., 2025; Hu et al., 2025; Hong et al., 2023; Lu et al., 2025 等)。但比单纯"使用工具"更深刻的飞跃，在于智能体**发明**工具的能力——例如针对其任务或环境动态生成代码片段。这种即时创造问题求解工具的能力不仅强大，更是智能的基石。正如本杰明·富兰克林所言："人是制造工具的动物（Man is a tool-making animal）。"

有趣的是，为复杂推理引入外部计算模块的想法并非新鲜事，在视觉领域尤为如此。早期工作如神经模块网络（Neural Module Networks, NMN）(Andreas et al., 2015) 引入了一个编排一组预定义函数的解析器，采用神经符号式（neuro-symbolic）的视觉推理路径。这条工作线启发了一系列有影响力的后继者（表 1）。与端到端模型不同，这些系统显式地表示每个推理步骤，产生透明、可检查的中间输出，为 tackling 复杂而组合式的视觉推理提供了一条富有前景的路径（译注：此处 "tackling" 系原文用词）。

然而，先前的工作通常在**单轮框架**内依赖**预定义工作流与静态工具集**，限制了现代 LLM 智能体通过动态工具所能达到的灵活性、创造性与适应性。随着当今 MLLM 编码与推理能力的不断增强，我们在视觉推理中已能超越这些约束：模型可以在多轮设置中动态生成代码片段，即时构建量身定制的工具。

近期的进展如 OpenAI 的"Thinking with Images" (OpenAI, 2025) 凸显了这一潜力，但其对内部过程的可见性有限。在本报告中，我们展示并分析了具有强编码能力的先进 MLLM——本文以 GPT-4.1 (OpenAI, 2025) 与 Claude-4.0-Sonnet (Anthropic, 2025) 为例——如何动态创建并利用基于 Python 的视觉工具。我们提出 **PyVision**，一个交互式框架：模型在其中响应多模态用户查询，自主生成、执行并迭代精炼 Python 代码。为支撑这一动态工具循环，我们依托 Python 成熟库的丰富生态，并精心设计了系统提示与运行时环境，以实现 MLLM 与 Python 解释器之间无缝的多轮交互。

随后，我们深入分析了 PyVision 生成的工具。为此，我们构建了一个分类体系，将工具划分为四大类——基础图像处理、高级图像处理、视觉提示与草图（visual prompting and sketching）、数值与统计分析——外加一条由创造性、任务特定操作构成的长尾（图 1）。该框架使我们得以考察不同基准与领域如何激发出截然不同的工具使用模式。例如，感知密集型任务常触发裁剪与对比度增强等操作，而数学与逻辑基准更依赖视觉草图与数值分析。这些发现凸显了动态工具生成的力量：它赋予模型灵活性，使其策略能适应每个任务与领域的独特需求。

> **图 1**：用代码克服幻觉式启发（Overcoming Illusory Heuristics with Code）。该视觉谜题模仿著名的埃布斯豪斯错觉（Ebbinghaus illusion）(Jaeger and Klahs, 2015)，但有一个反转：它颠倒了典型的尺寸语境，使正确答案对人类在视觉上一目了然。然而，标准 MLLM (OpenAI, 2025) 会错误地回忆起广为人知的错觉模板而回答"大小相同"。相比之下，PyVision 表现出智能体性：探测像素值、分割物体，并通过即时生成的 Python 代码计算实际尺寸，从而得出正确答案。该示例凸显了动态工具如何实现超越表层模式匹配的、自适应、有根基、可验证的视觉推理。

各主要基准上的结果表明，PyVision 持续提升强后端模型的性能。值得注意的改进包括：PyVision-GPT-4.1 在 V\* (Wu and Xie, 2024) 上 +7.8%，在 Visual Puzzles (Song et al., 2025) 上 +8.3%，以及在 VLMsAreBlind-mini (Rahmanzadehgervi et al., 2024) 上的戏剧性跃升——PyVision-Claude-4.0-Sonnet 从 48.1% 提升至 79.2%，增幅高达 +31.1%。我们的结果表明，PyVision 充当后端模型固有优势的**放大器**：与感知能力强的 GPT-4.1 搭配时，在感知任务上收益更大；与 Claude-4.0-Sonnet 搭配时，则在抽象推理上收益更大。简言之，动态工具并不覆盖模型能力，而是将其释放。

归根结底，具备动态工具的智能体化 PyVision 不仅带来实际性能收益，也标志着多模态推理领域一场更广泛的转变。通过赋能模型即时发明新的计算工具，我们正更接近多才多艺、自主且真正有创造力的 AI 系统——它们能够在真实世界的视觉推理场景中自适应。

## 2 PyVision 框架

我们提出 PyVision——一个面向多模态推理的交互式、多轮框架。PyVision 赋予 MLLM 在推理期间动态生成并执行 Python 代码的能力。在每个会话中，MLLM 接收输入、生成 Python 代码作为响应，并在一个隔离的 Python 运行时中执行它。产生的输出——文本、视觉或二者兼有——被回送进 MLLM 的上下文，使其能够跨多轮迭代并精炼推理，直至产出最终答案。

与依赖固定工具集（如检测 (Liu et al., 2024) 或分割 (Kirillov et al., 2023) 模型）的既有方法不同，PyVision 仅提供 Python 作为工具的构建积木。该设计利用了 Python 丰富的科学与视觉库生态，例如 OpenCV (Bradski, 2000)、Pillow (Clark et al., 2015)、NumPy (Harris et al., 2020)、Pandas (McKinney et al., 2011)、Scikit-learn (Pedregosa et al., 2011) 与 Scikit-image (Van der Walt et al., 2014)。借助这一多才多艺的生态，模型可以生成高度自适应、面向多样任务量身定制的工具。

### 2.1 系统提示设计

为引导 MLLM 的推理与代码生成，PyVision 在用户查询之外使用一个精心构建的**系统提示（system prompt）**。系统提示编码了操作性指令，规定如何访问输入图像、组织代码以及返回最终答案。关键组件包括：

- 鼓励 MLLM 生成代码来求解任务；
- 输入图像或视频帧被预加载为名为 `image_clue_i` 的变量（i 为图像索引），使模型无需额外加载代码即可引用图像；同时提供图像分辨率，以辅助裁剪等操作；
- 代码输出通过特定函数产生：文本结果用 `print()`，图像可视化用 `plt.show()`；
- 每个生成的代码块包裹在 `<code>` 标签中，以实现可靠解析；
- 最终答案封闭在 `<answer>` 标签中，以保证评估的一致性。

> **图 2**：PyVision——一个能够动态生成工具的交互式多轮框架，面向多模态推理设计。在一次推理会话中，PyVision 与 Python 解释器进行 n+1 轮交互。图中 `code_block_i` 表示 MLLM 在第 i 轮生成的 Python 代码，`mm_clue_i` 表示 Python 解释器执行产生的多模态输出。该循环持续进行，直到 MLLM 输出最终答案。

在这一设计下，我们实验所用的两个 MLLM——GPT-4.1 (OpenAI, 2025) 与 Claude-4.0-Sonnet (Anthropic, 2025)——能够可靠地生成可解析、可执行、极少崩溃的代码块。完整系统提示见附录 A。

### 2.2 运行时与 MLLM 的多轮交互

如图 2 所示，PyVision 作为 MLLM 与隔离 Python 运行时之间的多轮智能体循环运行。在第 i 轮，MLLM 生成代码块 `code_block_i`，其执行产生多模态结果 `mm_clue_i`；这些结果被追加到 MLLM 的上下文中，使其能在下一轮更新推理。循环持续到 MLLM 自行决定输出最终的带框（boxed）答案为止。

为支撑 MLLM 与 Python 运行时环境之间稳健而有效的多轮交互，PyVision 融入了若干设计原则：

- **进程隔离（Process isolation）**：每个代码片段在由主进程动态派生的子进程中执行，确保一次执行中的崩溃或副作用不会影响整个推理会话；
- **跨轮持久化（Cross-turn persistence）**：运行时环境跨轮保留变量与状态，使模型能够复用或修改此前各轮的中间执行结果——例如先裁剪图像，再施加滤波，最后计算几何特征以完成任务；
- **文件系统安全的 I/O（File-system safe I/O）**：运行时与 MLLM 之间的通信通过结构化变量传递 (Feng et al., 2025; Xue et al., 2025; Gou et al., 2023) 并由系统提示引导来完成，避免对宿主文件系统的直接依赖。

这些机制共同使 PyVision 成为一个面向多模态推理任务动态工具生成的灵活、安全且强大的平台。

## 3 动态生成的工具

**不同任务与领域中的示例。** 我们首先在图 4、图 5、图 6、图 8 以及图 7（译注：原文此处以脚注链接指代图 7 的找不同案例）中，展示 PyVision 在多样任务与领域中的示例。这些示例说明 PyVision 如何自主创造面向每个独特挑战的任务特定与领域特定工具——这些工具从 PyVision 的多轮代码生成与执行中**自愿涌现**（emerging voluntarily），而非任何预先设计的结果。

### 3.1 工具分类体系

为更好地理解 PyVision 所生成工具的类型，我们基于其在各种任务与领域（第 4 节）中产生的代码构建了一个分类体系。具体而言，我们收集推理会话中生成的代码片段，通过 OpenAI API 使用 text-embedding-3-large (OpenAI, 2025) 对其进行嵌入，并对嵌入进行聚类以识别涌现的工具类别。通过检视与解释所得簇，我们识别出四大类主要工具——(1) 基础图像处理、(2) 高级图像处理、(3) 视觉提示与草图、(4) 数值与统计分析——以及 (5) 长尾操作（译注：原文表述为"四个大类"，但列出了五项，第 (5) 项为不入主要类别的长尾操作，与引言中"四大类 + 长尾"的说法一致）。以下分别详述。

#### 基础图像处理（Basic Image Processing）

这些工具是视觉操作与感知的基石，使模型能够以改进下游推理的方式清洗、对齐并凸显图像内容。

- **裁剪（Cropping）**：对高分辨率或杂乱的输入，PyVision 常裁剪并放大感兴趣区域。通过推理选取坐标，它实际上执行了"软目标检测"，把注意力聚焦在最要紧之处（图 3）。
- **旋转（Rotation）**：错位的图像（如旋转的地图、倾斜的文档）甚至会困扰强模型。PyVision 将输入旋转到规范朝向，使文本、空间布局或方向线索更易解读。
- **增强（Enhancement）**：在医学影像等视觉上细微的领域，PyVision 施加对比度调整等增强手段，使潜隐结构更加显著（图 4）。

#### 高级图像处理（Advanced Image Processing）

这些工具反映 PyVision 执行中高层视觉任务的能力，只是这些任务是按需动态设计与执行的。

- **分割（Segmentation）**：通过阈值化或边缘检测隔离特定区域，PyVision 能从背景噪声中提取前景目标。
- **检测（Detection）**：PyVision 生成边界框或边缘检测来定位场景中的物体，支撑计数或测量等后续操作（图 5）。
- **OCR**：不依赖外部 API，PyVision 自行提取文本内容（如路牌、标签），实现混合的视觉-语言推理（图 3）。

#### 视觉提示与草图（Visual Prompting and Sketching）

在某些任务中，仅感知图像并不够——模型必须"视觉地思考" (Yang et al., 2023; Hong et al., 2024; Bai et al., 2024; Zheng et al., 2024)。为辅助自身推理，PyVision 在图像上标注辅助记号，本质上是在创建视觉笔记或草图。

- **渲染标记（Rendering Marks）**：在目标计数或枚举任务中，PyVision 常用点或符号标记条目。这种外部记忆充当计数辅助，帮助其跟踪已经数过什么（图 6）。
- **渲染辅助线（Rendering Lines）**：在几何或空间任务（如迷宫）中，PyVision 绘制辅助线辅助推理，例如展示迷宫中的移动方向。

#### 数值与统计分析（Numerical and Statistical Analysis）

为从感知走向解释，PyVision 调用对视觉输入进行定量推理的工具。

- **图像直方图（Image Histogram）**：通过绘制像素强度分布，PyVision 可以分析光照、对比度等属性——在直方图承载含义的领域尤为关键（图 4）。
- **数值分析（Numerical Analysis）**：求解视觉数学问题或比较数量时，PyVision 编写脚本计算面积、长度或其他度量，以支持符号推理（图 5）。

#### 长尾操作（Long-Tail Operations）

PyVision 还会发明不易归类的崭新工具。这些一次性操作展示了其在新颖约束下创造性推理的能力。例如图 7 中（译注：原文该处引用编号同样指向图 7 所附脚注链接），为求解"找不同"任务，PyVision 直接对两张图像做像素值相减并可视化差值结果。这种零样本的问题分解与工具合成，体现了动态工具在视觉推理中的力量与灵活性。

> **图 3**：案例研究：视觉搜索（Visual Search）需要基于语言的世界知识、基于视觉的语境理解，以及精确锁定特定视觉元素的迭代精炼。此例来自 V\* (Wu and Xie, 2024)，智能体须在复杂室外场景中识别一块小型广告牌上的文字。目标仅占图像极小区域，需要自适应裁剪——这展示了动态工具生成如何实现灵活的空间推理。智能体跨三轮迭代生成定制 Python 代码，基于视觉反馈不断精炼基于坐标的裁剪工具，最终隔离出用户查询所需的广告牌；随后执行 OCR 并提取出 "YOGA" 等关键文本，正确判定该商户为瑜伽馆。

> **图 4**：案例研究：医学影像分析（Medical Imaging Analysis）往往需要高视觉敏感性与领域特定推理才能解决细微的医学问题。此例来自 OmniMedVQA (Hu et al., 2024)，涉及在视网膜眼底图像中识别特定异常，PyVision 被要求在没有任何领域特定模块的前提下做出诊断。首先，PyVision 生成一个施加直方图均衡化以增强关键区域对比度的可视化工具——这是医学影像分析中的标准技术；接着创建第二个工具绘制强度直方图，确认不存在异常峰值。几轮之内，PyVision 从零构建了一条定制诊断流水线，正确得出"无特定异常"的结论。这凸显了 PyVision 为复杂医学任务生成可解释、领域自适应工具的能力。

> **图 5**：案例研究：符号视觉谜题（Symbolic Visual Puzzles）要求精确的空间推理以及对重叠或紧邻几何基元的识别——这对人类简单，对强大的 MLLM 直接求解却出奇地困难 (Rahmanzadehgervi et al., 2024)。相比之下，此类谜题的规则结构使其非常适合基于代码的求解。这是 VLMsAreBlind (Rahmanzadehgervi et al., 2024) 中的嵌套正方形计数任务：PyVision 先用 `skimage.measure.find_contours` 进行边缘检测，识别出十条轮廓；继而推断轮廓数对应五个嵌套正方形——每个正方形贡献内外两条边。为验证这一点，模型进行数值分析并打印检测轮廓的排序周长；第三阶段进行复核，自信确认正确答案：五个嵌套正方形。

> **图 6**：案例研究：视觉草图（Visual Sketching）是人类求解科学问题（包括数学与物理）的宝贵策略，它也能通过精确数值计算与视觉推理提升 AI 模型表现 (Hu et al., 2024)。此例来自 MathVision (Wang et al., 2024)，PyVision 被要求计算四张排成一行的桌子周围能坐多少人。模型先勾勒桌子布局，渲染标记来表示四张相连的桌子及周围就座的人，并从草图推断可坐十人；第二轮中，PyVision 生成一张示意图来解释并验证落座逻辑，标出不适合就座的位置。

> **图 7**：案例研究：找不同（Spot-the-Difference）展示了结构化的视觉比较。给定并排的图像对，PyVision 被要求找出所有视觉差异。PyVision 首先规划多步策略：把图像分成左右两半、计算像素级的绝对差值、生成差值图以凸显变化；随后将两张原图与计算出的差值可视化并排显示以辅助分析，并据此枚举识别出的差异。尽管最终答案并未完全正确，模型主动采用像素级差分并组织推理流水线的做法值得注意。该示例同时说明了智能体视觉推理的创造性潜力与缓解幻觉的持续挑战（脚注 1：数据来源 <https://www.jabobaby.com/blog/posts/photo-hunt>）。

> **图 8**：案例研究：视频理解（Video Understanding）受益于跨帧整合推理与定向选帧的智能体流水线。此例来自 VSI-Bench (Yang et al., 2024)：给定一段 3 分钟的室内第一人称（egocentric）视频，PyVision 须确定房间里桌子的数量。PyVision 先分析视频以检测含桌子的候选帧；随后选择并展示各显示一张不同桌子的关键帧——餐桌、书桌、茶几与边桌——以支撑推理。通过综合多视角的视觉证据与文本推断，PyVision 得出房间里有四张不同的桌子。

#### 智能体工具化的视频推理（Video Reasoning with Agentic Tooling）

与静态图像任务相比，视频理解提出了独特的挑战。PyVision 在此场景中展现出强大潜力：它不把视频当作整块输入，而是当作一系列**决策点**。图 8 中，PyVision 并不穷尽分析所有帧，而是动态选择并仅处理那些包含不同类型桌子的帧，进而提取视觉证据支撑推理。这种智能体式的多步工作流使 PyVision 的运作更像人类分析师：略读、采样，并基于中间结果精炼理解。

### 3.2 跨任务与领域的工具使用模式分析

**基准。** 为评估 PyVision 在多样基准与领域上的有效性，我们选择六个基准，详情如下：

- **多模态数学**：MathVista (Lu et al., 2023) 与 MathVision (Wang et al., 2024) 以结合视觉感知与数值推理的数学问题挑战模型。
- **领域与逻辑推理**：MMMU (Yue et al., 2024) 用多模态输入测试跨学科的具体学科推理，常需大学水平知识；VisualPuzzles (Song et al., 2025) 聚焦逻辑，任务覆盖算法、类比、演绎、归纳与空间推理，在最小化领域依赖的同时最大化抽象。
- **符号视觉**：VLMs Are Blind (Rahmanzadehgervi et al., 2024) 由精心设计的符号视觉谜题构成，探查对抽象、结构化视觉基元的解析与推理极限。
- **细粒度视觉搜索**：V\* (Wu and Xie, 2024) 含 191 个高分辨率样本，要求基于细微查询精确定位微妙的视觉细节，是注意力与空间推理的强测试床。

我们还评估了两个特殊领域——医学影像 VQA (Hu et al., 2024) 与遥感 VQA (Kuckreja et al., 2024)——以探查不同领域中的工具使用模式。

**工具分布。** 为理解 PyVision 如何让工具适配不同问题，我们在图 9 中分析了各基准与领域上工具类别的分布。

结果揭示了强烈的任务与领域特定偏好。在 MathVista (Lu et al., 2023)、MathVision (Wang et al., 2024)、MMMU (Yue et al., 2024)、VisualPuzzles (Song et al., 2025) 等数学与逻辑密集的基准上，PyVision 频繁生成数值与统计工具以支撑符号与定量推理，且常伴随视觉提示与草图，帮助把抽象逻辑扎根于视觉线索。在 VLMsAreBlind (Rahmanzadehgervi et al., 2024) 等符号视觉任务上，高级图像处理工具占主导，反映了对结构提取与视觉解析的需求。在 V\* (Wu and Xie, 2024) 等细粒度视觉搜索任务上，裁剪以超过 83% 的占比压倒性地占据主导，因为模型把注意力聚焦于局部区域。

领域同样扮演重要角色：在医学图像 (Hu et al., 2024) 上常使用对比度增强以揭示细微视觉模式；在遥感 (Kuckreja et al., 2024) 上分割工具更为常见，帮助在大尺度场景中勾画物体。这些结果凸显了动态工具生成的重要性——它使模型能够灵活地为手头任务量身定制策略。

> **图 9**：跨基准与领域的分类分布（Taxonomy Distribution Across Benchmarks and Domains）。工具使用随任务与领域显著变化。在数学与逻辑相关基准（如 MathVision、MathVista、MMMU、VisualPuzzles）上，数值与统计工具占据主要份额，视觉提示的使用也相对更频繁。在符号视觉任务 VLMsAreBlind 上，高级图像处理工具占主导。在 V\* 的视觉搜索中，PyVision 主要依赖裁剪来辅助细粒度视觉查询——占全部所用工具的 83% 以上。工具偏好亦对领域敏感：医学图像上频繁调用对比度增强工具；遥感上分割工具更常见。这些观察凸显了灵活、动态的工具对支撑现实世界视觉任务多样需求的重要性。

## 4 多样基准上的结果

**基线。** 为评估 PyVision 在多样多模态场景中的有效性，我们在多个基准上以 GPT-4.1 (OpenAI, 2025) 与 Claude-4.0-Sonnet (Anthropic, 2025) 作为后端进行测试，并采用普通思维链提示 (Wei et al., 2022; Kojima et al., 2022) 作为基线。推理参数设置与提示细节见附录 A。

**表 2：六个基准上的性能。** 相对各自基线的提升列于分数下方。**

| 模型 | MathVista | MathVision-mini | MMMU | VisualPuzzles | VLMsAreBlind-mini | V\* |
|---|---:|---:|---:|---:|---:|---:|
| GPT-4o | 61.4 | – | 68.7 | 41.1 | – | 73.9 |
| o1 | 71.8 | – | 77.6 | 51.8 | – | 69.7 |
| o3 | 86.8 | – | 82.9 | 54.0 | – | 95.7 |

| Claude-4.0-Sonnet | 71.4 | 48.0 | 74.4 | 42.7 | 48.1 | 56.5 |

表中值得强调的增益包括：PyVision-GPT-4.1 在 V\* 上 +7.8%，PyVision-Claude 在 VisualPuzzles 上 +8.3%、在 VLMsAreBlind-mini 上 +31.1%。\*GPT-4.1 结果为作者于 2025 年 6 月以普通思维链提示自行收集（详见附录 A.2）。

**结果。** 表 2 凸显了加入 PyVision 的动态工具后，两个强后端模型在多样基准套件上获得的一致提升。对 GPT-4.1 而言，PyVision 在每个数据集上均带来增益：从数学中心任务上的温和提升（MathVista +1.8%、MMMU +2.4%），到细粒度视觉搜索基准 V\* 上可观的 +7.8%。Claude-4.0-Sonnet 则呈现更尖锐的模式：数学与通用推理任务提升约 +3% 至 +5%，而 VLMsAreBlind-mini 上的符号视觉性能飙升 +31.1%。简言之，动态工具生成带来广泛的、依赖任务的增益，且增益大小也取决于后端模型的能力——下文将对此展开讨论。

**PyVision 放大后端 MLLM 最擅长的能力：推理或感知。** 为理解 PyVision 的性能增益与后端模型固有优势之间的关系，我们聚焦两个代表性基准：强调抽象推理的 MathVision-mini (Wang et al., 2024) 与凸显感知能力的 V\* (Wu and Xie, 2024)。Claude-4.0-Sonnet 在抽象推理上更强——其 MathVision-mini 表现（48.0%）高于 GPT-4.1（46.4%）——从 PyVision 获得的提升也更大（+3.3%，相比之下 GPT-4.1 的增益更温和，为 +2.3%）。反过来，GPT-4.1 在 V\* 等感知任务上占优（68.1% 对 Claude-4.0-Sonnet 的 56.5%），借助 PyVision 获得的改进也显著更大（+7.8%，而 Claude 仅 +0.3%）。这一互补模式表明，PyVision 所提供动态工具的有效性关键取决于后端模型的基础推理与感知优势。

进一步支持该假设的是 Qwen2.5-VL-72B (Bai et al., 2025) 的实验：较弱的抽象推理能力（MathVision-mini 上 18.4%）只带来有限提升（+1.7%），而较强的感知表现（V\* 上 67.0%）则转化为可观的增益（+10.0%）。这些洞见强调：PyVision 放大的是后端模型的既有优势，推理与感知的相互作用对于解锁动态多模态工具的全部潜能至关重要。

> **图 10**：跨任务与后端模型的多轮交互模式（Multi-Turn Interaction Patterns Across Tasks and Backend Models）。直方图展示了六个基准上每次查询所生成代码块数量的分布。PyVision-GPT-4.1（蓝）与 PyVision-Claude-4.0-Sonnet（红）呈现不同的交互模式：Claude 持续更频繁地生成代码且轮数更多。每个子图的图例标注了至少包含一个代码块的样本比例。

**MLLM 多久生成一次代码、生成多少？** 图 10 展示了 PyVision 分别以 GPT-4.1 与 Claude-4.0-Sonnet 为后端时，六个基准上每个用户查询生成代码块数量的分布。每个子图可视化模型在多轮推理中使用代码的频率，图例标注了包含任意代码生成的查询会话比例。我们观察到，Claude-4.0-Sonnet 在所有领域上一致地比 GPT-4.1 生成更多代码，常有更长的工具链并达到 100% 的代码覆盖率；反之，GPT-4.1 倾向于使用更少的代码块。这些趋势提示了二者智能体行为的差异，反映出两个 MLLM 在解析任务复杂度与利用代码支撑推理上的底层差别。

## 5 相关工作

### 5.1 多模态工具使用（Multi-Modal Tool Using）

为以更透明、可解释的方式求解组合式视觉问答（VQA）任务，早期工作 NMN (Andreas et al., 2015) 使用启发式方法，而 IEP (Johnson et al., 2017) 训练一个 LSTM 网络作为程序生成器。在 LLM 时代，预训练 LLM（如 GPT-4）被用于生成程序。

Visual ChatGPT (Wu et al., 2023)、MM-REACT (Yang et al., 2023)、HuggingGPT (Shen et al., 2023)、Image-of-Thought (Zhou et al., 2024) 与 VAT (Liu et al., 2025) 设计工作流来处理 VQA 输入并产出最终答案。VisProg (Gupta and Kembhavi, 2023) 与 ViperGPT (Surís et al., 2023) 为特定视觉任务预定义静态工具集，并提示 LLM 或 MLLM 生成调用这些工具的程序以支撑推理。随着 LLM 编码能力的提升，Visual Sketchpad (Hu et al., 2024) 预定义工具集并提示 LLM 即时编程执行代码，提供了更多灵活性。这些先前工作依赖包含各种视觉解析器 (Girshick, 2024) 的静态工具集——例如检测模型 GroundingDINO (Liu et al., 2024) 与分割模型 SAM (Kirillov et al., 2023)——这限制了跨视觉任务的通用性，并使外部模型成为瓶颈。相比之下，PyVision 仅以 Python 作为唯一的原子工具。凭借当今 MLLM（如 Claude-4.0 (Anthropic, 2025) 与 GPT-4.1 (OpenAI, 2025)）先进的编码与多模态理解能力，它们能编写 Python 代码即时构建并执行复杂工具，实现更通用、更灵活的推理。

### 5.2 思考图像（Thinking with Images）

在 o3 的博客 (OpenAI, 2025) 中，"思考图像"被呈现为一项诱人的特性。CoGCoM (Qi et al., 2025) 合成程序集成的数据，教 MLLM 在推理时使用预定义工具。DeepEyes (Zheng et al., 2025)、Pixel Reasoner (Su et al., 2025)、OpenThinkIMG (Su et al., 2025) 与 Chain-of-Focus (Zhang et al., 2025) 通过强化学习激励 MLLM 发展"用预定义工具思考图像"的能力。在 PyVision 中，我们以 Python 作为工具创建接口来支持思考图像，使 MLLM 能基于不同场景自生成更复杂、更自适应的工具。

## 6 结论

我们提出 PyVision——一个使 MLLM 能够即时生成并执行 Python 代码的智能体框架。与此前的视觉编程工作 (Surís et al., 2023; Gupta and Kembhavi, 2023; Hu et al., 2024) 不同，PyVision 无需视觉解析器与预定义的静态工具集：它从具体查询与视觉输入出发动态生成工具。我们在多种基准与视觉推理场景（如医学、多模态数学问题、遥感与视觉谜题）上评估了其有效性与灵活性，其在多样基准上展现出显著的性能提升。

## 创新点提炼

1. **以 Python 为唯一原子工具的动态工具生成范式**。与 ViperGPT、VisProg、Visual Sketchpad 等依赖预定义静态工具集（内置检测/分割等视觉解析器）的方法不同，PyVision 只提供 Python 语言及其科学计算生态，由 MLLM 针对具体查询与视觉输入即时编写并执行工具。这移除了外部模型这一瓶颈，从根本上提升跨任务通用性，也使"发明工具"而非仅仅"调用工具"成为可能。

2. **面向动态工具循环的工程化多轮运行时**。PyVision 将推理组织为 MLLM 与隔离 Python 运行时之间的 n+1 轮智能体循环，并以三条设计原则保障稳健性：进程隔离（子进程执行防止崩溃扩散）、跨轮持久化（变量与状态跨轮保留，支持"裁剪→滤波→计算几何特征"式的增量工具链）、文件系统安全的结构化 I/O（避免对宿主文件系统的直接依赖）。配合精心设计的系统提示（预加载 `image_clue_i` 变量、`<code>`/`<answer>` 标签协议、分辨率注入），使 GPT-4.1 与 Claude-4.0-Sonnet 生成的代码极少崩溃。

3. **首个对动态生成工具的系统化分类学与跨域使用模式分析**。作者收集推理会话中生成的代码，用 text-embedding-3-large 嵌入并聚类，归纳出基础图像处理、高级图像处理、视觉提示与草图、数值与统计分析四大类及长尾操作，并量化揭示工具使用的任务/领域敏感性：V\* 上裁剪占 83% 以上，符号视觉任务以高级图像处理为主，数学逻辑任务以数值统计为主，医学靠对比度增强，遥感靠分割。

4. **"放大器"效应的实证发现**。实验表明 PyVision 的增益并非无差别，而是放大后端模型的既有优势：感知强的 GPT-4.1 在感知型基准 V\* 上获得 +7.8%，抽象推理强的 Claude-4.0-Sonnet 在 VLMsAreBlind-mini 上获得 +31.1%；Qwen2.5-VL-72B 的结果（V\* +10.0% 对 MathVision-mini +1.7%）进一步佐证。这一"动态工具不覆盖、而是释放模型能力"的论断，为后端模型选择与动态工具部署提供了可操作的指导。

5. **可解释、扎根视觉证据的智能体推理路径**。从 Ebbinghaus 反例（模型拒绝套用广为人知的错觉模板，转而探查像素值并计算真实尺寸），到医学影像中自建"均衡化→直方图→诊断"流水线，PyVision 展示了把推理扎根于可验证视觉证据的能力；作者亦坦诚记录失败案例（找不同任务答案不全对），指出幻觉缓解仍是挑战——兼具方法论价值与实验诚实性。

6. **完整的开源可复现资源**。论文公开了完整系统提示、推理代码与 HuggingFace 在线 Demo，附录提供 10 类工具的真实生成代码片段，为后续"智能体 + 代码 + 视觉"研究（包括以强化学习训练"思考图像"的路线）提供了可直接对比的强基线与工具接口设计范本。
