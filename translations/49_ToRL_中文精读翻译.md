## 摘要

我们提出 ToRL（Tool-Integrated Reinforcement Learning，工具集成强化学习）——一个旨在训练大语言模型（LLM）通过直接从**基座模型**（base model，即未经后训练的模型）扩展强化学习、从而自主利用计算工具的框架。与基于监督微调的方法不同，ToRL 使模型能够通过不受限制的探索来发现最优的工具使用策略。在 Qwen2.5-Math 基座模型上的实验展示了大幅改进：ToRL-7B 在 AIME24 上取得 43.3% 的准确率——超过无工具集成的 RL 14%，并超过现有最佳的工具集成推理（Tool-Integrated Reasoning, TIR）模型 17%。进一步的分析揭示了若干涌现的**认知行为**——例如策略性的工具调用、对无效代码生成的自我调节，以及在计算式与解析式推理之间的动态切换。这些能力无需任何显式指令，仅通过奖励驱动的学习即可涌现。我们在 https://github.com/GAIR-NLP/ToRL 开源了实现、数据集与模型。

## 1 引言

大语言模型的近期进展已经证明，强化学习可以带来卓越的推理能力。o1、R1 与 Kimi 等模型在大规模 RL 训练下展现出回溯（backtracking）、自我修正（self-correction）与反思（reflection）等涌现能力 (Team, 2024; Guo et al., 2025; Team et al., 2025)。若干开源工作也展示了类似的可喜结果 (Qin et al., 2024; Huang et al., 2024; Zeng et al., 2025; Luo et al., 2025; Ye et al., 2025)。

语言模型的传统推理依赖纯自然语言方法，如思维链（Chain-of-Thought, CoT）(Wei et al., 2022)。这类方法虽然对许多任务有效，但在面对复杂计算、方程求解或需要精确计算的过程时会失效 (Gao et al., 2023; Chen et al., 2022)。尽管已有不少围绕代码生成模型的研究，很少有方法能够通过强化学习成功架起 LLM 推理能力与计算工具执行能力之间的桥梁。工具集成推理（Tool-Integrated Reasoning, TIR）早在近期的 RL 扩展突破之前就已被探索：它使模型能够通过编写代码来调用外部工具、通过解释器执行代码，并根据代码输出迭代地生成后续推理。ToRA、MathCoder 与 Qwen2.5-Math-Instruct-TIR 等实现证明了 TIR 在增强数学问题求解方面的有效性 (Gou et al., 2023; Wang et al., 2023; Shao et al., 2024; Liao et al., 2024; Yang et al., 2024)。

尽管有这些进展，现有 TIR 方法仍面临关键局限。多数研究从更强的模型蒸馏轨迹后执行监督微调（Supervised Fine-Tuning, SFT），这把模型限制在预先设定的工具使用模式上，并束缚了对最优策略的探索。虽然也有工作（如 Qwen-Math）对 SFT 训练后的模型应用 RL，但有限的实现透明度使人难以理解工具在 RL 框架内是如何集成的。为应对这些挑战，我们提出 ToRL（Tool-Integrated Reinforcement Learning）——一个直接从基座模型扩展强化学习、不受先前监督微调约束的框架。与以往在 SFT 模型上做增量改进的方法不同，ToRL 支持从零开始的 RL 训练，使模型能够通过大量探索发现最优的工具使用策略。这种扩展方式产生了与"建立在预设模式之上"的方法在质上不同的行为。

我们在 1.5B 与 7B 两种规模的 Qwen2.5-Math 基座模型上的实验表明：ToRL 的性能显著优于无代码解释器的传统 RL，也优于在 TIR 环境中的 Qwen2.5-Math-Instruct (Yang et al., 2024)。值得注意的是，我们的 7B 模型在 AIME 上取得 43.3% 的准确率，可媲美某些用强化学习训练的 32B 模型 (Hu et al., 2025)。

通过大量分析，我们揭示了关于工具集成学习动力学的若干关键洞察：

- **代码使用演化**：随着训练推进，模型用代码求解的问题占比稳步上升，同时语法正确、可执行代码的比例也不断增长。这证明模型自主习得了有效的工具使用策略。
- **对无效代码的自我调节**：无需显式指令，模型学会识别并减少无效代码模式的生成，提示一种关于工具效用的元认知（metacognition）正在涌现。
- **工具调用频率的权衡**：提高每题允许的最大工具调用次数能显著增强性能，但也带来严重的计算开销，揭示了工具集成学习中一个关键的效率-效果权衡。

这些发现揭示了 ToRL 如何孕育多样的认知行为，包括从代码执行中获取反馈、计算式与分析式方法之间的交叉验证，以及根据问题特征自适应地选择推理策略。这些行为是通过奖励驱动的学习、而非对人类设计模式的模仿涌现出来的，这表明工具集成强化学习是提升 LLM 推理能力的一个有前景的方向。

为支持后续研究，我们开源了实现与训练模型，使社区能够在 ToRL 之上构建与扩展，推进工具增强的语言模型。

> **图 1**：上图为 ToRL 与基线模型的性能对比（16 步滑动平均）。两图分别展示 1.5B 与 7B 模型上 AIME24 准确率（%）随训练步数的变化。两种情形下，ToRL（Ours）都显著优于无工具基线与 Qwen-2.5-Math-Instruct-TIR，最高分别高出 12%（1.5B）与 14%（7B）。下图为训练中涌现的认知行为示例（求两条抛物线 $y=2x^{2}$ 等对应的交点参数 $k+m$）：模型先用自然语言推理解出交点并得到 $k+m=-1+(-8)=-9$；随后写代码计算 `k_m_sum = k + m` 并执行，输出为 16；发现推理结果与代码输出不一致后，模型没有直接采信任何一方，而是说"代码输出是 16……让我们重新检查代码和步骤"，再次调用工具同时打印交点坐标与 $k+m$（输出为 `[(-2, 18), (8, 38)]` 与 `16`），确认代码无误后以推理复核，最终给出 $\boxed{16}$——体现出"计算结果与推理结果交叉验证、发现不一致时进行反思并借助工具进一步核实"的行为模式。

## 2 方法论

### 2.1 数据集构建

我们从 NuminaMATH (Li et al., 2024)、MATH (Hendrycks et al., 2021) 与 DeepScaleR (Luo et al., 2025) 中的奥林匹克级数学竞赛题构建数据集。初始过滤移除了证明类问题与验证标准模糊的题目，得到 75,149 道可验证题目。随后我们应用 LIMR (Li et al., 2025)——一种强化学习数据蒸馏技术——提取难度分布均衡的高质量样本。该过程最终得到 28,740 道题目，作为所有后续实验的基础。

### 2.2 工具集成推理（Tool Integrated Reasoning）

（译注：原文本小节标题拼写为 "Tool Intergrated Reasoning"，系原文笔误，应为 "Tool Integrated Reasoning"。）

> **图 2**：同一问题的 CoT 与 TIR 解法示例。问题为"确定 $\frac{1}{(6\cdot 10)^{10}}$ 的十进制表示中小数点后紧跟着多少个零"。(a) CoT 示例：模型先化简分母 $(6\cdot 10)^{10}=(60)^{10}=(6^{10}\cdot 10^{10})$，把表达式拆为 $\frac{1}{6^{10}}\cdot\frac{1}{10^{10}}$；随后判断 $\frac{1}{10^{10}}$ 是直接决定小数点后连续零个数的项——它等价于把小数点左移十位，得到小数点后连续九个零（第十位为 1），并认为 $\frac{1}{6^{10}}$ 只影响这九个零之后的数字而不改变连续零的个数，从而给出答案 9。(b) TIR 示例：模型把问题拆解为四步（计算 $6\cdot 10$、求十次幂、求其倒数的十进制表示、统计小数点后紧随的零个数），随后编写 Python 代码：以 `base = 6 * 10`、`power_value = base ** 10`、`reciprocal = 1 / power_value` 计算倒数，将结果转为字符串、取小数点后的部分并逐字符统计前导零，解释器输出 17，模型据此给出最终答案 17。（译注：CoT 的推理看似层层有据却得出错误答案 9——它忽略了 $\frac{1}{6^{10}}$ 同样会带来前导零；而 TIR 借助代码执行得到正确答案 17，直观展示了纯语言推理在精确数值计算上的固有局限。）TIR 使模型能够编写代码、调用解释器获取所执行代码的输出，再基于执行结果进行进一步推理。

工具集成推理（TIR）(Gou et al., 2023; Wang et al., 2023; Shao et al., 2024; Liao et al., 2024; Yang et al., 2024) 使 LLM 通过在推理过程中纳入可执行代码来克服自身的计算局限。与传统的提示方法不同，TIR 通过"推理—代码执行"的迭代过程，显著提升数值计算与逻辑任务上的准确率。

形式化地，给定语言模型 $M$、一个执行 $M$ 所写代码以获取工具调用结果的代码解释器 $I$、以及输入问题 $Q$，TIR 在第 $k$ 步构造推理轨迹 $s_{k}$：

$$s_{k}=\{r_{1},c_{1},o_{1},\dots,r_{k},c_{k},o_{k}\} \tag{1}$$

其中 $r_{i}$ 表示自然语言推理，$c_{i}$ 表示生成的代码，$o_{i}$ 是 $c_{i}$ 的执行结果。迭代生成过程遵循：

$$(r_{k},c_{k})=M(Q\oplus s_{k-1}) \tag{2}$$

$$o_{k}=I(c_{k}) \tag{3}$$

$$s_{k}=s_{k-1}\oplus r_{k}\oplus c_{k}\oplus o_{k} \tag{4}$$

该循环持续到模型给出最终答案为止，每一步都以先前的代码执行结果为条件。基于计算反馈对推理路径的动态调整，使模型能够验证中间步骤，并在复杂问题求解过程中纠正错误。

### 2.3 ToRL：工具集成强化学习

我们提出 ToRL（Tool-Integrated Reinforcement Learning）——一个将 TIR 与强化学习结合、直接从基座语言模型出发而无需先前监督微调的框架。现有方法通常在已经通过 SFT 对齐的模型上应用 RL，而我们的方法证明：通过恰当设计的强化学习，工具增强的推理能力可以从基座模型中有效涌现。

在常规的推理 RL 中，模型生成 CoT 轨迹并依据答案正确性获得奖励。然而，CoT 在需要精确计算或穷举的场景下经常失败。我们的方法用工具集成的推理路径替代这些纯语言轨迹，将代码解释器（Code Interpreter）模块直接集成到 RL 环境交互循环之中。

#### 2.3.1 TIR 采样（Rollout）框架

为使模型自动输出带代码块的推理，我们使用图 3 所示的提示。在模型的采样（rollout）过程中，当检测到代码终止标识符（```output）时，系统暂停文本生成，提取最新的代码块并执行，然后将结构化的执行结果以 ```output\nOBSERVATION\n``` 的格式插入上下文，其中 OBSERVATION 为执行结果。随后系统继续生成后续的自然语言推理，直到模型给出最终答案或产生新的代码块。值得注意的是，当代码执行失败时，我们刻意把错误信息返回给 LLM——我们假设这些错误诊断信息能增强模型在后续迭代中生成语法与语义均正确的代码的能力。

> **图 3**：ToRL 的提示模板（训练时 prompt 占位符会被替换为具体题目）：「用户与助手之间的一段对话。用户提问，助手解题。\nUser: 请将自然语言推理与程序相结合来解决上述问题，并把你的最终答案放在 \boxed{} 中。\n{prompt}\nAssistant:」

我们观察到，采样过程中集成工具会引入显著的 GPU 空闲时间，采样速度与工具调用频率成反比。为将训练速度维持在合理范围内，我们引入超参数 $C$——单次响应生成中模型可进行的最大工具调用次数。一旦超过该阈值，系统将忽略后续的代码执行请求，迫使模型切换到纯文本推理模式。

#### 2.3.2 ToRL 的设计选择

1. **工具调用频率控制**。我们观察到，采样中集成工具会带来显著的 GPU 空闲时间，采样速度与工具调用频率成反比。为维持合理的训练效率，我们引入超参数 $C$，表示单次响应生成中允许的最大工具调用次数。一旦超过该阈值，系统将忽略后续的代码执行请求，迫使模型切换到纯文本推理模式。（译注：此条内容与 §2.3.1 末段重复，原文如此。）

2. **执行环境选择**。为平衡训练效率与效果，我们需要一个稳定、准确且响应及时的代码解释器实现。我们最初测试了 qwen-agent（https://github.com/QwenLM/Qwen-Agent）的 Python 执行器，其延迟极低；但其执行环境与训练系统之间缺乏隔离，执行错误（如非法内存访问导致的段错误）可能危及整个训练过程。我们最终选择了 Sandbox Fusion（https://bytedance.github.io/SandboxFusion/），它提供隔离的执行环境；尽管延迟略高，但能为持续性训练操作提供更优的稳定性。

3. **错误信息处理**。我们实施了特定的错误处理优化以增强训练效果。当 Sandbox Fusion 遇到执行错误时，它会生成包含无关文件路径信息的冗长 traceback。为缩减上下文长度、只保留相关的错误信息，我们仅提取错误信息的最后一行（例如 NameError: name 'a' is not defined）。

4. **沙箱输出掩码**。在损失计算时，我们对来自沙箱环境的 OBSERVATION 输出做掩码处理。这能防止模型试图记住具体的执行输出、而非学习可泛化的推理模式，从而显著提升训练稳定性。

#### 2.3.3 奖励设计

我们实现了一个基于规则的奖励函数：答案正确获得奖励 1，答案错误获得 −1。此外，代码解释器天然提供关于代码可执行性的反馈。基于成功执行代码与解题正确率之间的相关性，我们引入了一个基于执行的惩罚：包含不可执行代码的响应将招致 0.5 的奖励扣减。

**表 1：答案正确性奖励**

| 答案正确性 | 奖励值 |
| --- | --- |
| 正确 | 1 |
| 错误 | −1 |

**表 2：代码可执行性奖励**

| 代码可执行性 | 奖励值 |
| --- | --- |
| 可执行 | 0 |
| 不可执行 | −0.5 |

## 3 实验

### 3.1 实验设置

**训练**。所有 RL 实验均使用 veRL (Sheng et al., 2024) 框架进行，以 Sandbox Fusion 作为代码解释器。我们采用 GRPO (Shao et al., 2024) 算法，采样（rollout）批大小设为 128，每道题生成 16 个样本。为增强模型探索，所有实验均省略 KL 损失并将温度设为 1。我们选择 Qwen-2.5-Math (Yang et al., 2024) 系列模型作为 RL 的基座模型。为最大化效率，默认调用次数 $C$ 设为 1。此外，默认实验只保留答案正确性奖励，不纳入代码可执行性奖励——后者将在 §3.3 中讨论。

**评估**。评估时所有模型均使用贪心解码（temperature = 0）。我们在若干有挑战性的数学基准上评估结果：(1) AIME24；(2) AIME25；(3) MATH500 (Hendrycks et al., 2021)；(4) OlympiadBench (He et al., 2024)；以及 (5) AMC23。

### 3.3 分析

为深入理解 RL 如何促使模型调用工具辅助推理，我们在 §3.3.1 中定量分析模型的工具使用与代码编写行为，并在 §3.3.3 中展示有代表性的示例。此外，我们在 §3.3.2 中改变 RL 框架中与 ToRL 相关的关键参数，考察其对模型性能与训练效率的影响。

#### 3.3.1 第一部分：训练中的代码行为

> **图 5**：训练期间的工具使用动态。(a) 代码占比（Code Ratio）：包含代码的响应比例；(b) 通过率（Pass Ratio）：已执行代码中无错误运行的比例；(c) 正确/错误响应中的通过率：比较正确响应与错误响应的执行成功率；(d) 有效代码占比（Effective Code Ratio）。

图 5 提供了对训练中工具使用模式的洞察，具体如下：

**代码占比**。图 5(a) 展示了前 100 步内模型生成的响应中包含代码的比例，该比例从 40% 增长到 80%，在训练全程保持稳步提升。

**通过率**。图 5(b) 展示了成功执行代码的比例，呈持续上升趋势，反映出模型编码能力的增强。

**正确与错误响应的通过率**。图 5(c) 描绘了正确与错误响应各自的代码通过率，揭示出代码执行错误与最终答案准确率之间的相关性——正确的响应表现出更高的代码通过率。

**有效代码占比**。图 5(d) 考察了有效代码占比的变化，聚焦两个关键指标：

- **已执行代码占比**（Executed code ratio）：解释器成功执行的被生成代码所占比例，其中排除了因超过最大工具调用次数 $C$ 而被省略的代码。（译注：原文此处 "due to due to" 系重复笔误。）
- **最终答案前代码占比**（Before final answer code ratio）：模型给出最终答案之前生成的代码所占比例，忽略仅在答案生成之后用于正确性验证的代码。

两项指标都随时间增长，表明模型所生成代码的有效性随训练推进而提升。

**Takeaway-I**：随着训练步数增加，模型用代码求解的问题比例以及能被正确执行的代码比例持续增长；与此同时，模型在训练过程中会识别并减少无效代码的生成。

#### 3.3.2 第二部分：关键设置的影响

> **图 6**：ToRL-1.5B-C=2 表示超参数 $C$ 设为 2；ToRL-1.5B-ErrorPenalty 表示在奖励函数中纳入代码可执行性奖励，对执行错误的代码施加惩罚。

本节探讨 ToRL 关键设置对最终性能与行为的影响。

首先，我们考察增大 $C$（采样时单次响应生成中可调用的最大工具次数）的效果，具体比较 $C$ 设为 1 与 2 时对模型性能的影响。如图 6(a) 与 6(b) 所示，将 $C$ 设为 2 能显著提升性能，使平均准确率提高约 2%。然而，如表 4 所示，增大 $C$ 会大幅降低训练速度，因此需要在性能与效率之间做出权衡。

进一步地，我们分析了在奖励塑形（reward shaping）中纳入代码可执行性奖励的影响。图 6(c) 与 6(d) 表明，这一奖励设计并不能提升模型性能。我们的假设是：对执行错误引入惩罚，可能激励模型生成过于简单的代码以尽量减少出错，这反过来会妨碍其正确解题的能力。

**Takeaway-II**：增大 $C$ 能显著增强模型性能，但也会严重降低训练效率；纳入代码可执行性奖励不能提升性能。

## 4 结论

我们提出 ToRL，它使 LLM 能够通过强化学习在推理中集成工具，从而超越预设的工具使用约束。我们的结果显示了显著的性能增益与涌现的推理能力，凸显了 ToRL 在推进 LLM 复杂推理方面的潜力。

## 创新点提炼

1. **直接从基座模型扩展工具集成 RL（跳过 SFT）**。与"从强模型蒸馏轨迹→SFT→再 RL"的主流路径不同，ToRL 证明：仅靠规则奖励与不受限制的探索，工具增强的推理能力即可直接从基座模型中涌现。这消除了对预设工具使用模式的依赖，也使训练出的行为在性质上不同于模仿蒸馏数据的方法。

2. **把代码解释器嵌入 RL 环境交互循环的 TIR Rollout 框架**。检测到 ```output 终止标识符即暂停生成、抽取最新代码块送沙箱执行、把 OBSERVATION 以结构化格式插回上下文继续解码，并由统一的提示模板驱动，使 GRPO 的每条采样轨迹都能自然穿插"推理—执行—再推理"的多轮循环，为强化学习提供了可训练的工具使用接口。

3. **一套面向训练稳定性与效率的工程化设计选择**。工具调用频率上限 $C$ 控制 GPU 空闲、Sandbox Fusion 提供隔离执行环境、错误信息只截取最后一行、以及对沙箱 OBSERVATION 输出做损失掩码——四项设计共同把"在 RL 循环中运行外部解释器"这一不稳定因素转化为可长期维持的训练系统，其中掩码机制从机制上防止模型记忆具体执行输出、只学习可泛化的推理模式。

4. **对训练中代码行为的四维定量分析**。以代码占比、通过率、正确/错误响应通过率之对比、有效代码占比（含"已执行代码"与"最终答案前代码"两个口径）四组指标刻画训练动态，实证了"模型自主习得工具使用策略、并主动抑制无效代码"这一元认知式演化，而非仅报告最终分数。

5. **关键设置的消融揭示效率-效果权衡**。$C$ 从 1 提高到 2 带来约 2% 的平均准确率提升，但单步耗时从 237 秒增至 288 秒（对照无工具的 118 秒）；而"不可执行代码扣 0.5"的惩罚项反而损害性能——提示该惩罚会诱使模型生成过于简单的代码。这些结论对后续工具集成 RL 的超参数选择具有直接参考价值。

6. **涌现认知行为的实证刻画**。模型在训练后期自发出现"根据执行反馈修正代码"（表 5）与"先自然语言推理、再用代码验证、发现矛盾后反思修正"（表 6）等行为；这些行为完全由奖励驱动涌现，没有任何显式指令或人工设计的模式，为"RL 扩展能产生新质的认知行为"提供了具体例证。这与摘要所强调的策略性工具调用、无效代码自我调节、计算式与解析式推理间的动态切换相呼应，也构成了本文区别于单纯刷分工作的核心叙事。
