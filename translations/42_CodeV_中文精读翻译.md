## 摘要

智能体式视觉-语言模型（agentic vision–language models）正越来越多地通过调用图像操作来"以图思考"（think with images）。然而，本文表明：**高最终答案准确率往往掩盖了不忠实的视觉推理**——模型可能在无关区域上调用工具、或完全无视工具输出，却仍然猜中正确答案。为此，本文首先提出一套忠实性评估协议（faithfulness evaluation protocol），用于度量中间视觉工具输出（例如裁剪图）是否真正包含被查询的证据。该协议揭示：近期的视觉智能体虽在视觉搜索基准上取得很高的最终答案准确率，其忠实工具使用率却很低。接着，本文提出 **CodeV**——一个以工具感知策略优化（Tool-Aware Policy Optimization, **TAPO**）训练的代码型视觉智能体。TAPO 是一个过程级（process-level）RL 框架：它在 GRPO 之上叠加**直接定义在视觉工具输入与输出之上**（而非思维链 token 之上）的稠密奖励，使监督更易于验证、更不易被奖励作弊（reward hacking）钻空子。CodeV 将视觉工具表示为可执行的 Python 代码，TAPO 则**仅基于问题与工具输出**分配逐步奖励，同时鼓励"必要的"与"证据一致的"工具使用。在两阶段 SFT+RL 流水线中，CodeV 在相关视觉搜索基准上取得有竞争力或更优的准确率，并大幅提升忠实工具使用率。在视觉搜索之外，CodeV 还在一系列多模态推理与数学基准上取得强劲表现，说明显式监督中间工具行为对于构建可信的智能体式视觉推理系统至关重要。

## 1 引言

大语言模型（LLM）与视觉-语言模型（VLM）如今已能处理需要扩展思考与工具集成推理（tool-integrated reasoning）的挑战性任务：网页搜索、代码执行以及面向复杂目标的智能体规划（Jaech et al., 2024; OpenAI, 2025; Guo et al., 2025; Team et al., 2025b, 2025a; Yao et al., 2022; Zhang et al., 2024; Lao et al., 2025, 2024）。在视觉领域，当前系统显式地"以图思考"（OpenAI, 2025），将推理与裁剪、分割等视觉动作交织（interleaving），使答案扎根（ground）于工具响应之中（Wu et al., 2023; Surís et al., 2023; Hu et al., 2024），在视觉推理（Lu et al., 2024）、视觉搜索（Wu and Xie, 2024）、图表推理（Wang et al., 2024）等组合式任务上取得显著增益。这一智能体式推理范式稳定优于单次预测（single-shot prediction），并为可靠、基于证据的解法提供了一条可扩展路径。然而，许多最强的智能体式系统都基于专有模型（GPT-4o、o3）。因此，本文聚焦于训练**开源** VLM，使其获得类似的智能体式视觉工具使用行为。

可验证奖励强化学习（RL with verifiable rewards, **RLVR**）已成为激发复杂推理的主流方法（Jaech et al., 2024; Guo et al., 2025; Team et al., 2025b）。近期工作将 RLVR 扩展到智能体式视觉推理：智能体学会把图像操作（如裁剪、分割、深度估计）与文本推理交织（Su et al., 2025b; Zheng et al., 2025; Su et al., 2025a; Huang et al., 2025）。通过代码解释器暴露图像，进一步允许模型调用丰富的图像操作库（如裁剪、旋转），并在多次工具调用间发挥其视觉能力，正如 OpenAI o3（OpenAI, 2025）及相关工作（Zhang et al., 2025）所展示的。这种**基于代码的接口**避免了对重量级外部工具 API 的依赖，并复用模型在预训练中已大规模见过的代码模式，使工具使用更具表达力也更自然。

尽管如此，本文观察到当前开源视觉智能体存在一个关键失效模式：DeepEyes（Zheng et al., 2025）与 Pixel-Reasoner（Su et al., 2025b）等模型能在视觉搜索基准上得高分，却依赖错误或错位的工具调用（例如裁剪了错误区域仍答对；见图 1）。这促成了第 3 节的忠实性分析：我们系统地评估*视觉工具使用*——检查中间图像操作（如裁剪图）是否真正包含问题所引用的物体或区域——从而度量视觉搜索的动作级忠实性。

> **图 1**：一个视觉智能体系统生成"不忠实"轨迹的示例——裁剪工具用在了错误区域、分析也并不忠实，但最终仍得到了正确答案。

基于这些实验结果，我们假设上述错位源于奖励作弊（reward hacking）（Skalse et al., 2022），其根源是奖励设计的两个关键问题：**(1) 结果主导（outcome dominance）**与 **(2) 奖励稀疏（reward sparsity）**。具体而言，现有奖励是"结果主导"的：它们只关心最终准确率或工具是否被调用，而对工具*如何*被使用毫无监督（Zheng et al., 2025; Zhou et al., 2025）。缺少步级信用分配（credit assignment），策略会迅速钻空子——幻觉出工具使用或执行无意义的操作。这与网页智能体发出浅层搜索查询或点击、却基本无视检索证据的模式如出一辙（Lao et al., 2025; Nakano et al., 2021; Zhang et al., 2024）。其次，奖励是**稀疏**的，导致优化动力学不稳定：困难任务的早期 rollout 经常拿零奖励，这打击了"部分正确地忠实使用工具"的尝试。虽然奖励塑形（reward shaping）或调用奖励能推动策略用工具，但它们同样引入奖励作弊，鼓励诸如不必要的图像操作、平凡计算之类的不忠实行为（Liu et al., 2025; Zheng et al., 2025; Feng et al., 2025）。随着模型规模扩大、RL 训练加浓，这些问题日益显著，放大了模型为"表面成功信号"而非"真实推理忠实性"而优化的倾向。基于上述观察，本文的核心研究问题是：

> **我们如何激励视觉-语言模型产生扎根于工具输出的忠实推理？**

为回答这一问题并激发更强的编程能力，我们从**过程奖励（process reward）**视角重新审视 RLVR，提出**工具感知策略优化（TAPO）**，把工具使用视为一串可验证的决策。TAPO 不只奖励最终答案，而是利用规则检查与一个评判模型（judge model）为每个工具输出分配*步级奖励*（step-level rewards）——评判仅需问题与答案的上下文即可对齐。TAPO 兼得 GRPO 的可扩展性与稠密的过程感知信号，且无需训练一个单独的、易被钻空子的奖励模型去监督不可验证的思维链。TAPO 强化学习进一步与冷启动指令微调阶段整合，构成两阶段课程训练框架；在此基础上，我们采纳并进一步精整常用的指令微调与 RL 数据集（Zheng et al., 2025; Wang et al., 2025c; Zhang et al., 2025）。在这些数据上训练的模型 **CodeV-7B**（基于 Qwen2.5-VL-7B（Bai et al., 2025））实现了稳定、忠实的工具使用，减少了工具相关的级联失败，并在 10 个挑战性基准上取得强劲表现，缩小了与专有系统的差距（OpenAI, 2025; Jaech et al., 2024）。本文主要贡献如下：

1. **工具感知策略优化（TAPO）**。提出一种新颖的策略优化方法，为"工具使用必要性"与"工具输出一致性"在 GRPO 上叠加稠密过程奖励；TAPO 带来显著更好的样本效率与训练稳定性。
2. **面向视觉智能体的忠实性评估**。提出一套检测不忠实视觉推理的协议，产出超越准确率的量化忠实性指标。
3. **忠实性与精度的实证增益**。用 TAPO 训练 CodeV 大幅提升视觉推理任务的工具忠实性，并在 10 个挑战性基准上展现强劲性能。
4. **开放的配方与资源**。发布 CodeV 完整训练配方（含 TAPO 实现）、数据集与对应模型，便于复现与扩展。

## 2 预备知识

### 2.1 面向推理 LLM 的强化学习

RLVR（Shao et al., 2024; Lightman et al., 2023）已被证明能有效激发 LLM 的多步推理（Guo et al., 2025; Jaech et al., 2024）。在该范式中，模型生成自己的轨迹，从奖励信号获得反馈，并迭代改进其策略。形式化地，给定提示数据集 $\mathcal{D}$，策略 $\pi_{\theta}$ 生成输出 $o$ 并获得奖励 $R(q,o)$。我们优化：

$$
\max_{\pi_{\theta}}\; \mathbb{E}_{x\sim\mathcal{D},\,o\sim\pi_{\theta}(\cdot|q)} \Big[ R(q,o) - \beta\,\mathbb{D}_{\mathrm{KL}}\big(\pi_{\theta}(o|q)\,\|\,\pi_{\mathrm{ref}}(o|q)\big) \Big], \tag{1}
$$

（译注：原文期望下标写作 $x\sim\mathcal{D}$，按语义应为 $q\sim\mathcal{D}$ 之笔误，此处保留原文记法。）其中 $\mathbb{D}_{\mathrm{KL}}$ 作为正则惩罚，约束更新后的策略靠近参考策略，从而在 PPO、GRPO 等策略梯度方法中稳定训练。在标准"仅结果"（outcome-only）设置中，$R$ 只施加于最终答案，对"哪些中间工具决策重要"不提供任何信号——这在智能体式 RL（尤其涉及视觉动作时）中会产生误导性的虚假信号。KL 项使 $\pi_{\theta}$ 靠近参考策略，既稳定训练，又保留了有用的 SFT 先验（如合理的工具使用模式）。

### 2.2 智能体式视觉推理（Agentic Visual Reasoning）

我们考虑通过迭代推理与工具使用来回答视觉问题的任务设定。给定输入 $\mathrm{x}=(V,Q)$（图像 $V$ 与文本查询 $Q$），策略模型 $\pi_{\theta}$ 生成一个至多 $T$ 轮对话的轨迹 $\tau=(\mathbf{x},a_{1},o_{1},a_{2},o_{2},\ldots,a_{T})$，其中每个动作 $a_{t}\sim\pi_{\theta}(\cdot\mid\mathbf{x},h_{t-1})$ 以输入与历史 $h_{t-1}=\{(a_{i},o_{i})\}_{i=1}^{t-1}$ 为条件。动作 $a_{t}$ 属于三类之一：`<think>` 自由文本思考；`<tool_call>` 调用工具的可执行 token；`<answer>` 终止轨迹的最终答案。观察 $o_{t}$ 仅当 $a_{t}$ 为 `<tool_call>`（产生输出，如变换后的图像、数字或错误信息）时存在；对 `<think>` 与 `<answer>`，置 $o_{t}$ 为空。这一统一动作空间使推理与工具使用可灵活交织，模型能基于中间结果动态调整策略而非遵循固定工作流。我们的形式化把智能体式视觉推理当作单一、连贯的决策过程：每个动作都以完整轨迹历史（包括此前全部执行结果）为条件。

多数近期工作遵循两阶段课程流水线（OpenAI, 2025; Huang et al., 2025; Liu et al., 2025; Zhang et al., 2025; Su et al., 2025b; Zhou et al., 2025; Chu et al., 2025; Li et al., 2025）：先监督微调（SFT），再强化学习。SFT 让模型接触高质量轨迹——工具被调用且其输出被织入推理——从而教会基本的工具使用模式；许多论文强调高质量、多样化轨迹数据的重要性，例如带自反思的试错（trial-and-error with self-reflection）（Su et al., 2025b）。随后，RL 优化一个显式奖励——通常基于最终答案正确性并附带工具调用奖励——在分布偏移下鼓励探索，并在目标数据分布上巩固高奖励行为。我们承认 SFT 作为冷启动步骤的重要性；但若 RL 阶段处理不当，训练很容易发散并产生不忠实轨迹。

> **图 2**：V\* 基准（Wu and Xie, 2024）上以"答案正确"为条件的忠实性。对该视觉搜索问题，裁剪（crop）被视为最有效的工具使用（Zhao et al., 2025; Zheng et al., 2025; Su et al., 2025b）。因此，本文把忠实工具使用定义为"工具裁剪出的图像捕捉到任意目标物体"，并评估多少正确答案同时是忠实的（图中紫色部分）。其余正确答案的工具使用未捕捉到目标物体，被视为不忠实（薄荷绿色部分）。近期视觉智能体最终答案准确率很高，却未能忠实使用工具；CodeV 在不牺牲准确率的同时大幅提升忠实性。

## 3 VLM 中不忠实工具使用的证据

忠实推理（faithful reasoning）是构建可信智能体 AI 系统的核心。当模型执行智能体式视觉推理并调用视觉工具时，其中间动作应当准确反映并依赖于这些工具返回的信息。如图 1 所示，若缺乏这种对齐，模型可能"因错误的理由得出正确的答案"，同时损害可解释性与可靠性。在视觉场景下，这种不忠实性使人无法分辨：模型究竟是真正"看到"了证据，还是在利用文本线索生成看似合理的输出。

为研究这一行为，我们设计了定量评估"模型把推理扎根于*视觉工具使用*"之忠实程度的实验。我们不检查模型生成的思维链 token，而是聚焦于**工具动作的后果**——后者更易验证。具体而言，我们检验中间工具输出（如裁剪图像）是否与问题保持相关，为"模型的推理是否遵循预期解题路径"提供直接代理（proxy）。

**1) 基线与基准。** 我们评估两个近期开源的 SOTA 模型——DeepEyes（Zheng et al., 2025）与 Pixel-Reasoner（Su et al., 2025b），二者均通过基于裁剪的工具使用训练智能体式视觉推理。实验在视觉搜索基准上进行：真实的作答应先在高分辨率图像中定位一个小物体，再描述其属性或关系。我们主要使用 V\*（Wu and Xie, 2024），并在第 5.3 节补充报告 HRBench-4K 与 Thyme（Zhang et al., 2025）上的结果。

**2) 评估设置。** 为诊断这些模型视觉工具使用的忠实性，我们评估中间裁剪图像是否真正包含问题所引用的物体或区域。这直接针对其基于裁剪的设计——在这类设计中，图像操作是将推理扎根于视觉证据的核心机制（Zhao et al., 2025）。具体而言，对每个样本，我们将原始问题与一张*中间*工具输出的裁剪图一并交给 GPT-4o（作为评判模型，judge），并提示其判断该裁剪图是否包含被查询的物体或区域。当模型产生多张裁剪图时，只要任一裁剪图被判定为包含目标，即视该次视觉工具使用为忠实。随后，我们在"最终答案正确"的条件下报告忠实与不忠实工具调用的比例。更高的忠实工具使用率，反映出模型的推理、预期视觉证据与任务目标之间更可靠的动作级对齐。包括提示构造在内的详细评估设置见附录 8。

**3) 结果。** 图 2 展示了"最终答案正确"条件下忠实与不忠实工具调用的占比。尽管两个模型的最终答案准确率相对较高，其中间工具调用却只有约一半被判定为忠实于原问题（DeepEyes 为 57%，Pixel-Reasoner 为 43%）。

**4) 启示。** 这些结果表明，高最终答案准确率**并不**保证强的智能体式视觉推理：模型常常能从答案选项等文本线索猜出正确答案，同时以不忠实的方式使用视觉工具。换言之，现有基准可能大幅高估底层的视觉工具使用能力。这提示：训练目标不仅应保证最终正确性，还应强制工具使用本身的正确性——无论在构建 SFT 数据集还是设计 RL 奖励时均是如此。因此，将中间工具使用与预期证据对齐，对于发展真正智能体式、可信的视觉推理系统至关重要。

## 4 方法

> **图 3**：CodeV rollout 与工具感知策略优化（TAPO）总览。模型处理图像 $I$ 与问题 $Q$ 组成的对，使用裁剪等工具生成中间结果以得出最终答案。工具忠实性由一个奖励模型打分：对裁剪这类工具，奖励模型基于目标物体在裁剪图中的可观察性为 $r^{\mathrm{tool}}$ 打分。最终答案正确性用作结果奖励。策略 VLM 以工具感知策略优化——一种 GRPO 风格的强化学习方法——微调。策略 VLM 会对同一 $Q$ 与 $I$ 进行多次带工具使用的 rollout；这些 rollout 由结合忠实性与正确性的混合奖励系统打分。最终奖励在组内归一化，用于估计策略 VLM 更新所用的相对优势。

本节将第 2.2 节的一般性智能体视觉推理形式化，实例化为一个"为视觉推理生成代码"（Code for Visual reasoning, CodeV）的智能体，并介绍我们的工具感知策略优化（TAPO）框架。

### 4.1 总览

图 3 概括了 CodeV 的训练流水线，包含两个主要阶段：监督微调（SFT）与基于工具感知策略优化（TAPO）的强化学习（RL）。其目标是同时针对忠实性与准确率优化模型。

第一阶段，SFT 通过在涉及图像操作（如裁剪、旋转）与多轮精炼任务的数据集上训练来初始化模型。该阶段确保高效的工具使用、最小化对直接作答的依赖，学到的知识用作参考策略。

第二阶段，与 GRPO 类似，TAPO 执行同策略（on-policy）rollout，并以蒙特卡洛式基线计算奖励。TAPO 在工具使用与准确率之间取得平衡，引导模型生成忠实的工具步骤，同时避免不必要或不忠实的动作。

奖励系统结合准确率与忠实性：奖励有用的工具输出（如相关裁剪），惩罚"懒惰"的工具使用——例如大而无信息的裁剪或错误的工具操作。

### 4.2 代码化的智能体 rollout

如第 2.2 节与图 3 所示，一个 rollout 为

$$
\tau=(\mathbf{x},a_{1},o_{1},\ldots,a_{T}),\qquad \mathbf{x}=(V,Q), \tag{2}
$$

其中 $a_{t}\sim\pi_{\theta}(\cdot\mid\mathbf{x},h_{t-1})$，$h_{t-1}=\{(a_{i},o_{i})\}_{i=1}^{t-1}$。在 CodeV 中，每个 $a_{t}$ 是以下三者之一：

- `<think>`：用于中间推理的自由文本；
- `<code>`：对 $V$ 进行操作的带定界符（delimited）Python 程序；
- `<answer>`：终止 $\tau$ 的最终答案。

只有完整的 `<code>` 块才会在一个受限的 Python 沙箱中执行；该沙箱对 $V$ 只读，并提供一小组确定性的图像/数学工具。执行返回观察 $o_{t}$（日志与可选的派生图像），并被追加到上下文中；对 `<think>` 与 `<answer>`，置 $o_{t}=\varnothing$。这样，工具使用被完全表示在作用于该混合动作空间的 token 级策略内部，无需外部控制器。沙箱实现细节见附录 12。

### 4.3 TAPO：工具感知策略优化

我们采用两阶段 SFT+RL 流水线训练 CodeV。

**阶段 1：SFT。** 我们强调冷启动 SFT 阶段的重要性。我们发现，Qwen2.5-VL 这类流行的指令微调模型无法把编程知识转化为解题能力：对这些模型直接做 RL 时，使用代码的 rollout 平均正确率低于直接作答。模型会很快收敛到纯文本推理，无法开展智能体式视觉推理。为激发"以代码配合图像"（Code with Image）的知识，模型需要经 SFT 冷启动。SFT 模型既用作初始化，也用作式 (1) 中的参考策略 $\pi_{\mathrm{ref}}$。

**阶段 2：带组基线的 GRPO。** 随后，我们在同策略 rollout 上执行 GRPO 风格优化。对每个提示组 $g$（对应单个图像-问题对），采样 $K$ 条轨迹 $\{\tau_{k}^{(g)}\}_{k=1}^{K}\sim\pi_{\theta}(\cdot\mid g)$，计算其奖励 $R(\tau_{k}^{(g)})$，并将*组基线*（group baseline）定义为简单的蒙特卡洛 critic：$b(g)=\frac{1}{K}\sum_{k=1}^{K}R\big(\tau_{k}^{(g)}\big)$。给定轨迹 $\tau$，记 $g(\tau)$ 为其所属提示组。我们定义轨迹级优势（advantage）为 $A_{t}=R(\tau)-b\big(g(\tau)\big)$，并将该值沿轨迹广播到所有时间步。

对状态 $s_{t}$（截至时刻 $t$ 的完整多模态历史）中的每个 token 级动作 $a_{t}$，构造重要性比率

$$
r_{t}(\theta)=\frac{\pi_{\theta}(a_{t}\mid s_{t})}{\pi_{\mathrm{ref}}(a_{t}\mid s_{t})}. \tag{3}
$$

TAPO 优化如下带裁剪的 GRPO 目标：

$$
\mathbb{E}_{\tau,t}\Big[\min\big(r_{t}(\theta)A_{t},\;\mathrm{clip}\big(r_{t}(\theta),1-\epsilon,1+\epsilon\big)A_{t}\big)\Big]-\beta\,\mathbb{E}_{q}\Big[\mathbb{D}_{\mathrm{KL}}\big(\pi_{\theta}(\cdot\mid q)\,\|\,\pi_{\mathrm{ref}}(\cdot\mid q)\big)\Big], \tag{4}
$$

它以组级优势与 PPO 式裁剪实例化了式 (1)，应用于同时包含语言与代码动作的轨迹。在高温采样下，组采样隐式地分配信用（credit）：由于轨迹在某些步骤上彼此不同、且更好的轨迹产生更高的 $R(\tau)$，所得优势 $A(\tau)$ 将选择性地提高那些起决定性作用的工具使用步骤的概率。

#### TAPO 的奖励设计

TAPO 采用混合奖励，将最终答案正确性与视觉工具使用的忠实性相结合：

$$
R(\tau)=\lambda_{\mathrm{acc}}\,r^{\mathrm{acc}}(\tau)+\lambda_{\mathrm{tool}}\,r^{\mathrm{tool}}(\tau), \tag{5}
$$

其中 $r^{\mathrm{acc}}$ 度量答案质量，$r^{\mathrm{tool}}$ 评估工具步骤，$\lambda_{\mathrm{acc}},\lambda_{\mathrm{tool}}\in[0,1]$ 为权重系数。令 $\mathcal{T}_{\mathrm{tool}}$ 为满足"$a_{t}$ 是 `<code>` 动作"的时间步指标集合，并聚合

$$
r^{\mathrm{tool}}(\tau)=\frac{1}{|\mathcal{T}_{\mathrm{tool}}|}\sum_{t\in\mathcal{T}_{\mathrm{tool}}}r^{\mathrm{tool}}_{t}. \tag{6}
$$

#### 答案奖励

对 $r^{\mathrm{acc}}$，当真值答案可用时（如数值或类别型 VQA），我们使用精确匹配或程序化匹配；对开放式任务使用 LLM-as-a-judge。在开放式视觉推理中，最终正确性本就依赖外部评判（Zheng et al., 2025; Zhang et al., 2025），因此 TAPO 复用同一基础设施，不带来额外部署负担。

#### 工具奖励即证据检查

早期实验表明，直接评判*模型生成的*代码与思考既脆弱又昂贵。与之不同，TAPO 只检查*非模型生成*的上下文：$(Q,\;o_{t},\;\text{metadata})$，其中 $Q$ 为原始问题，$o_{t}$ 为沙箱输出（裁剪图像或其描述、坐标、简单统计量）。评判模板被问及：当前工具结果是否为回答 $Q$ 提供了*任何*有用证据。特别地，评分细则（rubric）：(i) 鼓励任何清晰包含相关物体或区域的裁剪；(ii) 不要求裁剪包含全部相关物体。对涉及多个目标的问题，一条至少隔离出一个正确区域的轨迹会得到奖励而非惩罚。

这种基于证据的视角比诊断内部推理更易验证：评判永远看不到思维链或代码，只需回答"这条证据对回答该问题是否有用？"。基于 IoU、对照真值框的奖励是一种替代方案，但它需要稠密标注，且无法泛化到没有边界框的任务。我们基于评判的构造可作用于任意工具输出，只需极小改动即可复用于其他任务族。评判模型的选择上，我们采用 Qwen2.5-VL-32B 作为评判，并在 5.4 节给出以 GPT-5-nano 为评判的消融结果。

#### 红线与抑制懒惰裁剪

为避免奖励作弊与"平凡的大裁剪"，我们组合两种机制：

- **SFT 塑形**。SFT 阶段已经教会模型局部化、高分辨率的裁剪与多轮精炼：训练轨迹中很少出现大而无信息的框。RL 在这一先验周边微调，而非从零开始发现裁剪行为。
- **评判细则**。对每张裁剪图，评判被指示聚焦于"裁剪图像的*主要内容*是否清晰包含回答 $Q$ 所需的物体或区域"。极端巨大或杂乱的裁剪（目标很小或几乎不可见）通常无法通过该检查，得到低 $r^{\mathrm{tool}}_{t}$。我们还将明显的工具滥用（如把图像读/写当作草稿本）视为红线（red flag）并赋予负奖励。

这些技术共同抑制懒惰裁剪。同时，我们保持 $|\lambda_{\mathrm{tool}}|<|\lambda_{\mathrm{acc}}|$，使全局答案正确性始终是主导训练信号。

#### 无显式视觉搜索的任务

对不需要局部化视觉搜索的任务（如某些计数或描述问题），稠密工具奖励容易鼓励不必要的工具调用与奖励作弊。若无需工具即可正确作答，最优策略就是直接跳过工具。对此类任务，我们刻意让 $r^{\mathrm{tool}}_{t}$ 默认接近零，只对明确红线施加负奖励——如无效坐标、重复的空操作（no-op）裁剪、可避免的沙箱错误。

### 5.1 实验设置

**数据准备。** 高质量训练数据对激发视觉推理、使模型能解复杂任务至关重要。我们使用 Thyme-SFT（Zhang et al., 2025）——一个精心整理的数据集，含丰富的多步代码推理演示与直接作答样本。RL 训练数据则从 Thinklite-70K（Wang et al., 2025c）与 DeepEyes-47K（Zheng et al., 2025）等开源数据构建：先剔除需要外部知识的问题（如 OK-VQA（Marino et al., 2019）），再通过 Qwen2.5-VL-32B 自动检查加人工验证严格清洗噪声标签。我们还让 Qwen2.5-VL-7B 对每个问题作答八次，丢弃采样经验准确率超过 0.9 的样本——这能提升 RL 效率，因为这些样本的所有 rollout 获得相同奖励、没有相对优势。该数据集仅用于 TAPO 的 RL 阶段。细节见附录 9。

**实现细节。** SFT 阶段遵循 Thyme（Zhang et al., 2025）的设置，微调三个 epoch。RL 阶段，我们设计了提示模板，其系统提示显式规定所需格式，包括特殊 token `<think>`、`<code>`、`<answer>`，以及沙箱输出 token `<sandbox_output>`。详细提示配置见附录 13。训练超参数：rollout 批大小与训练批大小均设为 256，每个样本生成 8 条 rollout，共 200 步更新；采样温度 1.0，学习率 $1\times 10^{-6}$。实验使用 8 张 H200 GPU，SFT 与 RL 阶段分别耗时 255 与 288 GPU 小时。

### 5.2 CodeV 的性能

我们将 CodeV 与开源基线（Qwen2.5-VL-7B、Pixel-Reasoner-7B、Thyme-VL-7B-RL）及专有模型 GPT-4o 在一套全面的多模态感知与推理基准上比较。

**结果。** 图 4 汇总了结果（完整数字见附录 10 的表 3 与表 4）。在 VLMBlinds 上，CodeV 取得最佳分数（46.7），较 Qwen2.5-VL-7B 与 Pixel-Reasoner-7B 提高约 3 分、较 Thyme-7B-RL 提高约 8 分，并略超 GPT-4o（译注：附录表 3 中该值为 46.6，与正文 46.7 略有出入，两处均按原文保留）。这表明 TAPO 训练并不牺牲基础而有挑战性的感知任务上的性能。在大图视觉搜索基准（V\*、HRBench-4K-all、HRBench-8K-all）上，CodeV 整体表现强劲：在 V\* 上取得最高分 84.8，明显超过 GPT-4o（64.4）与 Qwen2.5-VL-7B（75.0）；在 HRBench-4K-all 与 HRBench-8K-all 上与最佳开源基线持平或略优，同时对 GPT-4o 保持可观领先，表明其在高分辨率下具备稳健的细粒度视觉推理。在偏数学的数据集上，CodeV 在 MathVista 达到 71.8（所有模型中最佳），在 MathVerse-Mini 达到 49.2，缩小了与 GPT-4o 的大部分差距并优于其他开源基线；在 MathVision-mini 上，CodeV 大幅超越 Qwen2.5-VL-7B 与 Pixel-Reasoner-7B，与 GPT-4o 保持竞争力。

总体而言，这些结果表明 CodeV 在感知与推理任务上同时缩小了开源与专有系统的差距。相对强基线 Qwen2.5-VL-7B 的一致增益说明：用 TAPO 的稠密过程级奖励激励视觉工具使用，为更强的智能体式 VLM 提供了一条有原则的路径。

### 5.3 推理忠实性评估

> **图 5**：V\* 与 HRBench-4k 基准上的忠实性比较。（Zhang et al., 2025）（即 Thyme）忠实工具使用率极低，源于其低工具使用率与思维链中的"装饰性"工具使用。

为评估 TAPO 设计所带来的忠实性，我们把第 3 节的分析扩展为"基线方法与 CodeV 的忠实性比较"，并额外加入 Thyme（Zhang et al., 2025）与 HRBench-4K 基准。我们报告忠实率，同时报告不忠实率与无工具使用率。更高的忠实工具使用率表明模型推理与问题意图之间对齐更好。

**结果。** 图 5 比较了 V\* 与 HRBench-4k 上的忠实工具使用率。CodeV 持续取得最高忠实性：在大多数设置下较 Pixel-Reasoner 与 DeepEyes 提升两位数（百分点），最极端情形下提升超过 30 个百分点，同时保持相当或更好的答案准确率。以相对值计，CodeV 的忠实工具使用率约为其他工具使用基线的 1.3–2 倍，表明 TAPO 有效鼓励模型把决策扎根于工具返回的证据。

相比之下，Thyme 在两个数据集上的忠实性都极低（V\* 与 HRBench-4k 上均为个位数）。人工检查发现，其 rollout 中真正调用视觉工具的不足 10%：它常常依赖纯文本推理，隐式地"假设已裁剪的图像"而不真正执行裁剪。这些发现凸显了显式忠实性评估与过程感知 RL 的重要性：没有步级激励，模型倾向于优化最终准确率而走工具使用的捷径。通过联合奖励答案正确性与忠实工具调用，TAPO 使 CodeV 在保持高准确率的同时大幅提升视觉推理的可靠性。更多工具使用分析见附录 11。

## 6 相关工作

### 6.1 视觉推理与工具使用

一系列工作通过组合图像操作或工具来探索智能体式视觉推理：从把复杂视觉任务表达为图像算子或统一 Python API 上可执行程序的 VisProg（Wu et al., 2023）与 ViperGPT（Surís et al., 2023），到提示 VLM 交织感知、搜索与计算、并将中间草图编辑为视觉思维链的 MM-ReAct（Yang et al., 2023）与 Visual Sketchpad（Hu et al., 2024）。更近期的方法中，MathCoder-VL（Wang et al., 2025a）在大规模图像-代码语料上训练模型以联合感知图像并书写可执行推理代码；Pixel-Reasoner（Su et al., 2025b）、DeepEyes（Zheng et al., 2025）、ViRFT（Liu et al., 2025）与 OpenThink-IMG（Su et al., 2025a）应用强化学习提升长程多模态推理；VISTA（Huang et al., 2025）与 Thyme（Zhang et al., 2025）则研究更灵活的工具接口与基于代码的工具抽象。本文建立在这些工具型视觉智能体之上，揭示其局限，从而推动"评估并训练忠实的视觉工具输出"这一新焦点。

### 6.2 思维链忠实性

早期 RLHF 系统如 InstructGPT（Ouyang et al., 2022）依赖 PPO（Schulman et al., 2017）与稀疏结果奖励，受限于信用分配缺陷。后续工作表明，带步级反馈的过程奖励模型在推理任务上可大幅超越纯结果监督（Lightman et al., 2023）；DeepSeekMath（Shao et al., 2024）则证明 GRPO 在仅结果奖励下仍可能诱发语言混杂等不忠实行为。更近期的框架（Tao et al., 2025; Xu et al., 2025）将可验证信号、稠密奖励模型分数与高奖励轨迹的同策略蒸馏结合，以稳定长程推理。与这些文本思维链方法互补，我们走另一条路：把可验证奖励直接附加到视觉工具输出上，提供把智能体动作与底层证据紧密耦合的步级监督。

## 7 结论

本文研究了如何训练执行忠实视觉推理的智能体式多模态模型。我们识别出当前开源模型中的不忠实行为，进而提出 CodeV——一个以工具感知策略优化（TAPO）训练的代码型视觉智能体；TAPO 是一个过程级 RL 框架，直接奖励忠实的视觉工具使用，而非只关注最终答案准确率。实验上，CodeV 在视觉搜索与推理基准上取得强劲性能与高忠实工具使用率。这些结果揭示了仅结果 RLVR 的关键局限，并强调了在训练智能体式多模态系统时显式监督工具使用的重要性。

### 局限与未来工作

尽管 CodeV 与 TAPO 在忠实视觉工具使用上取得进展，仍有若干局限。其一，TAPO 依赖一个静态评判模型，带来额外部署成本；微调一个奖励模型或自评判器（self-critic）来近似该评判是重要方向。其二，当前评判主要针对裁剪等以图像为中心的操作，尚不能为更丰富工具类型的输出忠实性提供通用度量。把框架扩展到更广的工具生态（如结构化知识库、动态网页环境），需要设计可扩展、可验证的工具忠实性概念及相应的任务专属奖励信号。

2. **SFT 数据（附录 9）**：从 Qwen2.5-VL-7B-Instruct 出发；直接 Zero-RL 会导致更新高度不稳定（策略要么钻工具奖励的空子、要么在引入惩罚后完全回避代码），故需冷启动。SFT 语料取自 Thyme-SFT（自 400 万+ 原始多模态样本蒸馏），含"书写并执行图像操作代码（高分辨率裁剪、旋转、对比度增强）+ 数学计算"的多步轨迹；选取单轮与二轮工具使用样本，共 333K 条。
3. **RL 数据（附录 9）**：从 Thinklite-70K 与 DeepEyes-47K 精整；剔除需外部知识的问题（如 OK-VQA）；用 Qwen2.5-VL-32B-Instruct 自动检查 + 人工验证清洗噪声标签；用 Qwen2.5-VL-7B-Instruct 对每题作答 8 次、丢弃经验准确率 > 0.9 的近平凡问题。来源分布上 FigureQA、ChartQA、V\*、IconQA 合计超过半数。
4. **感知基准全结果（附录 10.1，表 3）**：CodeV-7B-RL 在 VLMBlinds 46.6（GPT-4o 45.1、Thyme-RL-7B 38.6、DeepEyes-7B 41.2）；V\* 84.8（与 DeepEyes 并列最高）；HRBench-4K-FSP 91.0；HRBench-8K-ALL 71.3、FCP 60.3；MME-Realworld 三列 52.6/47.2/56.3。相对 Qwen2.5-VL-7B 全感知维度一致提升：+2.7（VLMBlinds）至 +9.8（V\*），MME-Realworld 亦 +7.5 至 +9.5。作者指出工具型模型在视觉搜索上的强势主要源于共享训练分布，而 CodeV 通过过程级 RL 进一步获得更稳定、更可泛化的增益。
5. **数学与推理基准全结果（附录 10.1，表 4）**：MathVista 71.8（全场最佳）；MathVerse-Mini 49.2（GPT-4o 50.2）；MathVision-Mini 33.6（GPT-4o 35.9，较 Qwen2.5-VL-7B 的 21.4 提升 +12.2）；MMMU 59.3（GPT-4o 68.7、InternVL3-8B 70.1）；CharXiv Reasoning 39.3 / Description 72.1。说明以视觉工具使用为主的训练管线在 TAPO 加持下具备更广的能力迁移。
6. **忠实工具使用全结果（附录 10.2，表 5，"忠实 AND 正确 / 总样本"口径）**：V\* 上 CodeV 84.8（准确率）/68.0（忠实），DeepEyes 84.8/49.7，Pixel-Reasoner 79.6/34.1，Thyme 82.7/7.0；HRBench-4K 上 76.1/33.5（对比最佳基线 24.7）；HRBench-8K 上 71.3/13.3。忠实性随分辨率与难度增加一致下降（V\* → HRBench-8K），凸显高分辨率下维持忠实推理的固有挑战；作者认为对此类任务，"把整图切分、独立分析"的多智能体系统更实际，但 CodeV 在难度上升时表现显著更稳健。
7. **消融全表与工具使用分析（附录 10.3、11）**：各训练阶段与奖励组件对不同基准影响不均（某些变体在 HRBench-FSP 或 CharXiv-Reasoning 等子集有增益，但常以其他基准退化为代价），而 CodeV 几乎在所有基准上一致强劲。工具调用次数分析：绝大多数回答使用 1–2 次工具调用，3 次以上极少（≤1%）；零工具答案不如 1–2 次工具的轨迹准确，超过 2 次无额外增益——CodeV 学会少量聚焦的工具调用而非过度调用（例如 HRBench-8K 上"恰好 2 次工具调用且正确"的样本占全部测试样本的 46.1%）。
8. **Python 沙箱设计（附录 12）**：三个目标——(i) 安全隔离：文件 I/O 全部路由到受控工作区、静态扫描危险文件系统操作并阻止、每次调用受严格 wall-clock 时限约束；(ii) 降低编码负担：自动归一化工作目录与相对路径、自动修补缩进等小问题、预定义输入图像路径与已加载图像等常见变量、预导入常用图像库、用轻量静态分析推断裁剪框并把坐标 clamp 到有效边界、跨调用维持 import 与变量定义；(iii) 稳健错误处理：每次调用包裹异常，失败时把错误信息返回给模型供其修订重写或绕过工具继续推理；另将可视化产物作为观察——monkey-patch 绘图后端（拦截 plt.show()），把图像捕获为 $o_{t}$ 返回。
9. **RL 提示模板（附录 13）**：RL 数据提示规定目标（可先生成并执行 Python 代码再作答）、Python 执行规则（外部沙箱执行、输出以 `<sandbox_output>` 返回、图像操作先加载再处理、保存处理图并打印文件名、计算需定义变量并打印、代码须包在代码块中）与严格输出格式（思考段 + 答案段）；感知奖励模型提示采用三档评分：清晰包含至少一个问题所提及物体 = 1，部分匹配 = 0.5，不匹配 = 0.25。
10. **训练动态（附录 14）与定性样例（附录 15）**：TAPO 训练中准确率、格式与工具使用三类奖励稳定单调上升（格式奖励迅速饱和于 0.3）；与此同时平均响应长度与每步平均工具调用数逐渐下降——表明 TAPO 抑制了"超长链或无谓调用"式奖励作弊，引导模型走向更短、更聚焦、更忠实的推理。附录 15 给出 2 个忠实正确样例（裁剪拖鞋/蜡烛区域后正确识别颜色）与 2 个不忠实样例（首次裁剪错过目标，或以近乎全图的懒惰裁剪作答）。

## 创新点提炼

1. **揭示"高准确率掩盖不忠实工具使用"这一系统性失效**。本文发现 DeepEyes、Pixel-Reasoner 等开源视觉智能体在 V\* 等基准上准确率很高，但答案正确的样本中仅约 43%–57% 的中间裁剪真正包含目标物体——模型常靠文本线索猜对答案，现有基准因此大幅高估工具使用能力。
2. **动作级忠实性评估协议**。不检查思维链 token，只检查工具动作的"视觉后果"：将中间裁剪图连同原问题交给 GPT-4o 评判是否包含被查询目标，任一裁剪命中即记 faithful，从而得到独立于准确率、可复现的量化忠实性指标，且天然抗"装饰性"工具调用。
3. **TAPO：把过程奖励直接挂在工具输入/输出上**。区别于监督思维链 token 的过程奖励模型，TAPO 的混合奖励 $R(\tau)=\lambda_{\mathrm{acc}}r^{\mathrm{acc}}+\lambda_{\mathrm{tool}}r^{\mathrm{tool}}$ 中，$r^{\mathrm{tool}}$ 仅基于"问题 + 沙箱输出"的证据检查评分（评判看不到代码与思维链），更易验证、更难被奖励作弊；辅以 SFT 塑形 + 评判细则抑制懒惰大裁剪，以红线负奖励惩治明显滥用，并保持 $|\lambda_{\mathrm{tool}}|<|\lambda_{\mathrm{acc}}|$ 使答案正确性仍是主导信号；对无需视觉搜索的任务让 $r^{\mathrm{tool}}$ 默认近零以免诱发多余调用。
4. **代码即动作空间 + 工程化沙箱**。CodeV 将视觉工具表示为受限沙箱中执行的 Python 代码（`<think>`/`<code>`/`<answer>` 三类动作统一进 token 级策略），无需外部控制器或重量级工具 API；沙箱在安全隔离（I/O 受控、危险操作扫描、超时）、代码容错（自动修补、坐标 clamp、跨调用状态维持）与产物即观察（拦截绘图后端返回图像）上做了系统设计。
5. **两阶段课程 + 严谨数据工程**。实验证明 Zero-RL 会落入"纯文本捷径"学习陷阱，冷启动 SFT（Thyme-SFT 精选 333K）是代码化工具行为的前提；RL 数据（Thinklite-70K + DeepEyes-47K）经外部知识剔除、自动 + 人工标签清洗、8 次采样剔除经验准确率 >0.9 的近平凡样本，提升组相对优势的有效性。
6. **忠实性与能力的双重实证收益**。CodeV（Qwen2.5-VL-7B 底座）忠实工具使用率达基线 1.3–2 倍（V\* 68.0 vs DeepEyes 49.7、Thyme 7.0），同时 V\* 84.8 超 GPT-4o（64.4）20 余分、MathVista 71.8 全场最佳、MathVision-Mini 较底座 +12.2——说明显式监督中间工具行为不仅提升可信度，也带来能力增益，且训练更短更省（响应长度与调用数随训练下降）。
